# 超市收银系统 V4.22.1 — EXE 白屏根治：首次配置向导 + 断连错误页

> 日期：2026-09-12 ｜ 关联：V4.22.0（P16批3）、V4.21.2（双轨打包）

## 一、问题（用户报障）

**打包的 EXE 无论是安装版还是绿色版、无论是 Win11 还是 Win7，打开就是一片白。**

## 二、根因

V4.20.0 起 EXE 壳默认加载 `http://127.0.0.1:3100/pwa/`（desktop-config.json 可改）。
目标机器上**服务端没有启动**（或没配服务器地址）时，`mainWindow.loadURL` 失败：
Electron 对加载失败**不渲染任何内容**，kiosk 全屏窗口只剩 backgroundColor 底色 →「一片白」。
壳层没有任何错误提示、没有重试入口、首次部署还要手工往 userData 里放 desktop-config.json —— 部署体验断裂。

> 注：三端部署形态本身是对的（服务端独立部署、收银端 EXE 独立包、手机端零安装网页），
> 缺的是 EXE 壳对「服务端未就绪」这一常态的兜底交互。

## 三、修复（V4.22.1）

### 1. 首次启动 → 服务器配置向导
- 无 `desktop-config.json` 且未设 `POS_SERVER` 时，先弹普通窗口（非 kiosk）`renderer/setup.html`：
  - 填服务器地址（默认记忆上次输入）→ 「🔍 测试连接」→ 「保存并启动」
  - 探活走**主进程** `GET {server}/health`（3s 超时，绕开渲染层 CORS）
  - 保存写 `%APPDATA%/超市收银系统/desktop-config.json`，页面显示配置文件路径
- 支持回车触发测试；「退出程序」链接绕过 kiosk 关闭拦截

### 2. 服务端未启动 → 断连错误页（绝不白屏）
- 启动分流：已配置 → 主进程先探活，**通过才建窗加载收银台**；探活失败 → 主窗直接加载本地 `renderer/neterr.html`
- 兜底双保险：`did-fail-load`（主框架、排除 -3 中止）也落错误页——覆盖探活通过后服务端恰好挂掉的竞态
- 错误页展示：服务器地址 / 失败原因 / 时间 + 排查清单（服务端是否启动、同网段、防火墙 TCP 3100）+
  「🔄 重试连接」（重探活，成功才进收银台，失败留在错误页刷新原因）/「修改服务器地址」（重开向导）/「退出」

### 3. 其他
- 旧本机 UI（`ui!=='pwa'`）分支不探活（它不依赖服务器），不受影响
- preload `DesktopShell` 扩展：`desktopInfo / testServer / saveServer / applyAndStart / retryConnect / openSetup`
- 版本号 4.21.2 → 4.22.1；双轨（modern Electron44/x64 + win7 Electron22.3.27/ia32）重新打包

## 五、部署指引（更新）

1. 服务端电脑：启动后端（端口 3100），防火墙放行入站 TCP 3100
2. 收银机：装 EXE（或绿色版直接跑）→ 首次弹出配置向导 → 填 `http://<服务端IP>:3100` → 测试连接 → 保存并启动
3. 之后开机启动即自动连接；服务端暂时没开也不白屏——错误页点重试即可
4. 手机端零安装：浏览器开 `http://<服务端IP>:3100/pwa/`，或扫后台二维码

## 六、遗留与备注

- 「服务端未启动也能打开收银界面、联网后自动同步」：PWA 收银台已具备（SW 壳缓存 + 价目表缓存 + 离线现金记账暂存补传 V4.19.0）。
  唯一必须联网的环节是**登录/取 token**；已登录状态断网可继续收现金单，恢复后自动补传。
- EXE 打包跳过代码签名（无证书），SmartScreen 首次运行提示「仍要运行」即可。
