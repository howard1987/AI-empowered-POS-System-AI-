# 超市收银系统 V4.9.13 —— 新增商品弹窗两处交互修复

日期：2026-09-09　范围：后台商品档案（products.js）+ 后端 /products/units　验证：Playwright 实机全过

## 一、问题背景（用户原话锚点）

> 新增商品中，单位下拉只有填入的数据，而不是已经建好的单位列表。分类"+"按钮无效，并未弹出新建分类。

## 二、根因与修复

| 问题 | 根因 | 修复 |
|---|---|---|
| ① 分类"+"无效 | `#catModal` 与建档弹窗 `#pModal` 同为 `z-index:50`，但 catModal 在 DOM 中更靠前 → 同层级后者在上，**分类弹窗弹出了但被建档弹窗整个盖住** | catModal / unitModal 加 `z-index:60`（子弹窗恒在主弹窗之上） |
| ② 单位下拉"只有填入的数据" | 原生 `<datalist>` 行为：输入框已有值（如条码查询自动填入"瓶"）时，下拉只显示**过滤后的匹配项**，用户误以为单位库只有这一条 | 弃用 datalist 作为主交互，改为**自绘选择面板**：聚焦/点击即显示全部单位，仅输入时过滤；点选回填；无匹配提示可直接输入新单位 |

## 三、改动清单

| 文件 | 改动 |
|---|---|
| `frontend-web/screens/products.js` | ① `#catModal` / `#unitModal` inline `z-index:60`；② 新增 `attachUnitPicker(input)`：自绘单位面板（绝对定位、z=70、mousedown 选词防 blur 抢焦点），挂到 `#mUnit`（新增）与 `#eUnit`（编辑）；③ 启动时拉取 `GET /products/units`，`unitList = 常用字典 ∪ 店内在用单位` |
| `backend/src/modules/products.module.ts` | 新增 `GET /products/units`：`SELECT DISTINCT base_unit`（未删除商品），返回店内在用单位清单 |

单位数据源现在 = **21 项常用字典**（个/瓶/袋/盒/箱/提/罐/听/支/桶/包/卷/双/套/片/块/斤/公斤/克/升/毫升）**∪ 店内已用单位** ∪ 会话内新增（「＋」弹窗/保存时自动扩充），三处同步（新增弹窗、编辑弹窗、包装单位 datalist）。

## 四、验证结果（Playwright 实机）

1. 点建档弹窗分类「＋」→ `catModal` display:flex 且 **elementFromPoint 命中分类弹窗本体（置顶 ✓，z=60）**
2. 单位框预填"瓶"后聚焦 → 面板显示 **全部 22 个单位**（个/瓶/袋/盒/箱/提…），不再是过滤后的单项
3. mousedown 点选「袋」→ 输入框回填"袋"、面板自动收起 ✓
4. `GET /products/units` 路由已映射（401 鉴权可达，登录后返回店内单位数组）

## 五、边界说明

- datalist 保留未删（键盘输入提示仍可用），面板为主交互。
- 原生弹窗层级规则教训已记：**同 z-index 下 DOM 靠后者在上**——子弹窗必须显式 z-index 高于主弹窗（此前 unitModal 恰好排在 pModal 之后侥幸可用，catModal 排在前面即中招）。
