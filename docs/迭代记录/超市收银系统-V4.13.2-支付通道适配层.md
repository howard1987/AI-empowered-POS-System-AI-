# 超市收银系统 V4.13.2 — 支付通道适配层（模拟通道先行）

> 日期：2026-09-09 · 设计方案 14.21 节 · 回归 25/25 + 实机烟测 7/7 + V4.13.1 防回归 12/12

## 一、背景与对齐

老板核对成熟收银做法：**扫顾客付款码（被扫 B-scan-C）→ 通道扣款 → 成功信号 → 落单+开钱箱+小票**，无店员人工核对到账环节。逐条对照结论：

| 成熟做法 | V4.13.2 前现状 | 本期处置 |
|---|---|---|
| 扫顾客码→通道扣款→成功信号 | 扫码=记账式手记流水，无通道应答 | ✅ 本期落适配层+模拟通道 |
| 无需二次确认到账 | V4.13.1 强制勾选确认（记账式代偿） | ✅ 通道成功应答驱动落单，确认自动摘除；mode=off 自动回退保留 |
| 单品退货 / 退款=货品真实金额 | 已具备（按行退+整单优惠按比分摊） | 不动 |
| 原路返还（微信返微信） | 内部账户真原路；微信/支付宝只留痕 | ✅ 本期通道真原路退 |
| 开钱箱+小票打印 | 未做 | ⏸ P1（随 Electron 钩子） |

## 二、落地内容

### 2.1 后端
- **`db/049_pay_gateway.sql`**：网关流水表 `pay_gateway_txns`（out_trade_no 唯一幂等、status 状态机、order_id 回填、refund_cents 累计、付款码只留后 4 位）+ 设置项 `pay.gateway.mode`（默认 mock）。
- **`src/modules/pay.gateway.ts`**（新）：
  - `detectChannel()`：微信 10~15 / 支付宝 25~30 开头，16~32 位数字——付款码前缀自动识别渠道；
  - `PayGatewayService.micropay()`：被扫扣款（幂等：同 out_trade_no 重放返回原应答，防重复扣款）；`query()` 查单；`refundInTx()` 事务内 CAS 原路退（累计防超额 40901）；
  - `MockPayAdapter`：即时成功，**付款码尾号 0000 模拟失败**（验证失败路径）；接口签名与真通道一致，资质到位切 WechatPay/AlipayAdapter 业务层零改动；
  - API：`POST /pay/micropay`（pos.sell）、`GET /pay/txn/:outTradeNo`。
- **`sales.module.ts`**：支付行支持 `gatewayOutTradeNo`——结账时强制校验「网关 SUCCESS + 金额逐分一致 + 未关联其他订单」（FOR UPDATE 防并发双挂），不满足 40902 拒绝；`sale_payments.external_no` 自动落通道流水号；流水回填 order_id。
- **`refund.module.ts`**：微信/支付宝退款按 external_no 匹配网关成功单 → CAS 原路退并回写（部分退 PART_REFUNDED / 满额 REFUNDED）；匹配不到（记账式手记）维持留痕。
- **`app.module.ts`**：注册 PayGatewayModule。

### 2.2 PWA（checkout.js，SW v23→v24）
- 「扫码」点结账 → 「📲 扫顾客付款码」弹窗：大字应收 + 扫码枪直扫回车 + **实时渠道识别提示**；确认即 micropay → 成功**自动落单**（无勾选确认步骤）；失败红字透出通道 failMsg。
- **记账式回退**：mode=off（40900）自动切回 V4.13.1 二次确认弹窗。
- **防重复入账**：通道已扣款但结账网络异常 → 不进离线暂存，保留购物车与通道流水提示重试（同流水幂等）。

### 2.3 三层防线（终结「谎报到账」）
1. 扣款层：成功流水只能由适配器写入；
2. 结账层：挂通道支付必须对上 SUCCESS 且逐分等额流水；
3. 退款层：原路退按通道流水 CAS 扣减，累计不超原扣款。
