# 超市收银系统 V4.9.12 —— 条码数据升级：纠错回写闭环 + 爬虫互补 + 批量导入 upsert

日期：2026-09-09　范围：条码数据链路（products.module）+ 批量导入语义 + 前端提示　回归：`tests/verify-v4912-barcode.mjs` 11/11 + Playwright 实机全过

## 一、问题背景（用户原话锚点）

> 我测试了一下，几个都不准确，而且还有一些常见的商品查询不到，我觉得这个方案不好，能否用爬虫程序抓取网络上的相关数据来填充呢？我们要考虑怎么让这个数据更合理与更真实。

**根因取证**：实测时 mxnzp 凭据（app_id/app_secret）未配置，链路只走了最末档 Open Food Facts 兜底——国货覆盖差、无售价、名称偶有噪声。测的是"裸兜底"状态，V4.9.11 方案的真实水平未体现。

**方向决策**（用户确认）：①mxnzp + 纠错回写闭环为主链路；②自建爬虫互补；③同期做 Excel/CSV 批量导入。

**爬虫选型实测**：京东/苏宁搜索页均为 SPA 壳，服务端抓不到数据（反爬+前端渲染），直接爬电商不可行；**必应中国 SSR 结果页实测可用**（标题直接含"农夫山泉饮用天然水 6921168509256"）→ 选作爬虫源。

## 二、核心设计："数据更合理与更真实"的三层答案

| 层 | 机制 | 效果 |
|---|---|---|
| ① 纠错回写闭环 | 建档/编辑/导入保存的商品数据**回写 barcode_cache（manual=true）**，同码再查优先采用 | 店员改过的字段=100% 真实数据；**越用越准、完全本地化**（契合本地部署原则） |
| ② 名称清洗 | 去营销词（旗舰店/正品/包邮/批发…）、剥站点后缀（"- 条形码查询 - 京东"）、剥条码数字 | 在线源/爬虫噪声不再进表单 |
| ③ 爬虫质量护栏 | 标题不含条码且无商品特征（规格/单位词）→ **放弃不入库** | 实测教训：无护栏会返回"知乎问答"类垃圾；宁缺毋滥 |

## 三、改动清单（逐条落盘）

### 后端 `src/modules/products.module.ts`

| 项 | 内容 |
|---|---|
| `db/047_barcode_cache.sql` | `barcode_cache` 表（barcode UNIQUE / name/spec/unit/price/brand / source / manual / hits）；设置 `barcode.crawler.enable`（默认 true）、`barcode.crawler.daily_limit`（默认 50） |
| 查询链升级 | 本店库 → **barcode_cache(manual=true)『本店确认档案』** → mxnzp（跳过时在 40404 里提示配置凭据）→ OFF → **爬虫缓存/实时爬**；命中均写入缓存（人工数据永不被在线源/爬虫覆盖：`GREATEST(manual,...)`） |
| `cleanName()/extractSpec()` | 营销词清洗 + 规格提取（550ml 等）+ 单位推断 |
| `crawlBingTitle()/crawlAndCache()` | 必应中国 SSR 标题抓取；**限速三重**：码间≥3s、每日上限（设置可调，0=禁用）、8s 超时；质量护栏（含条码 > 含规格/单位词 > 放弃）；结果带 `unverified:true` |
| 纠错回写 | `create()` / `update()` 保存成功后 `bcUpsert(code, ..., 'manual', true)` |
| 导入 upsert | `POST /products/import` 支持 `upsert`（默认 true）：条码已存在→按行覆盖更新（仅覆盖文件提供字段）+ 回写缓存；返回 `created/updated/fail` 分项 |
| `POST /products/import-file` | 新端点：前端读 xlsx/CSV → base64 上传，SheetJS 统一解析（**codepage 936 兼容 GBK 编码 CSV**），中英文列名自动映射（条码/名称/规格/单位/售价/进价/保质期/分类/供应商） |

### 前端 `frontend-web/screens/products.js`

| 项 | 内容 |
|---|---|
| 填充提示分级 | 确认档案显示「♻️ 本店确认档案（最真实）」；爬虫数据显示「⚠️ 网络参考数据请逐项核对——保存后自动回写为本店确认档案」 |
| 导入弹窗 | 保质期放开为可留空（文件即真相）；文案标明"条码已存在将按行覆盖更新"；结果标签改为 **新增 N / 覆盖更新 N / 失败 N** |

## 四、验证结果

**API 回归 `tests/verify-v4912-barcode.mjs`（11/11）**：本店码优先 → 农夫山泉码命中（清洗后 name=农夫山泉 spec=550ml）→ 建档回写 manual 缓存 → 同码再查确认档案 → 导入首轮 2 新增 / 二轮 2 覆盖更新 / 覆盖结果落库 → 爬虫垃圾标题被拒（知乎问答不入缓存）。

**Playwright 实机**：导入弹窗贴两行 → 「新增 2 覆盖更新 0 失败 0」→ 改价复导 → 「新增 0 覆盖更新 2 失败 0」；建档弹窗输农夫山泉码 → 提示"✅ 已从【开放商品库】自动填充：商品名称 / 规格"。测试数据已清理。

**爬虫护栏实测**：卫龙码 6902626000517 → 必应首条为知乎问答 → 护栏拒绝 → 明确 40404「条码库未收录…提示：配置 mxnzp 凭据可大幅提升覆盖率」（垃圾数据未入缓存）。

## 五、使用说明（重要：覆盖率现状与提升路径）

1. **当前数据源现状**：mxnzp 未配置（跳过）+ OFF + 爬虫护栏——国货覆盖仍有限，这是你体感"查不到"的主因。
2. **强烈建议：申请 mxnzp 免费凭据**（https://www.mxnzp.com 自助申请）→ 系统设置 → 商品与库存 → 填入 app_id/app_secret 即生效。国内覆盖率会质变。
3. **最快开局通道：批量导入**——商品中心 → 📥 批量导入 → 选供应商 Excel/老系统导出文件（xlsx/csv/txt 均可，GBK 编码 CSV 兼容）→ 条码重复自动覆盖更新。真实数据零猜测。
4. 爬虫仅兜底：全部源未命中才触发，限速低频，结果标黄"请核对"；确认保存即沉淀为本店确认档案。

## 六、已知边界

1. 爬虫依赖必应中国可达性与反爬策略，失败静默跳过（不阻塞建档）；`barcode.crawler.daily_limit=0` 可整体禁用。
2. 爬虫价格不可信（电商促销价噪声大）→ 一律不填 price，只填名称/规格/单位。
3. 导入覆盖更新不校验"售价≥进价"红线（批量场景以文件为准）；单笔建档/编辑仍强制校验。
4. `import-file` 与前端内置 xlsx 解析双通道并存：浏览器路径（本地解析预览）为主，API 路径供脚本/小程序后续复用。
