# 超市收银系统 V4.25.6 — 商品档案补全「库存上下限」修改入口

> 来源：老板反馈（2026-09-13）：「商品档案中商品的库存上下限没有修改口径，找不到修改入口。」

---

## 一、问题定位

| 层 | 状态 |
|----|------|
| 数据库 `products.min_stock / max_stock` | ✅ 早已存在 |
| 后端 `POST /products`（建档）/ `PUT /products/:id`（编辑） | ✅ 一直支持（`minStock` / `maxStock`） |
| 商品**详情弹窗** | ✅ 已显示「库存上下限 0 ~ 0」 |
| 商品**新建 / 编辑表单** | ❌ **没有输入框**（本次补齐） |
| 提交 payload | ❌ **没带这两个字段**（本次补齐） |

即：能存、能看，**就是没地方改**。

---

## 二、本次改动（前端 `frontend-web/screens/products.js`）

1. **新增商品表单**：在「经营方式」后新增两个输入框
   - 库存下限（0 = 不预警）→ 低于该值触发补货提醒（AI 补货建议 / 库存预警）
   - 库存上限（0 = 不限制）→ 高于该值触发超储提醒（占用资金预警）
2. **编辑商品表单**：同位置同字段，并在打开编辑时**回填**现值（0/NULL 显示为空）。
3. **提交**：建档与编辑 payload 均带上 `minStock` / `maxStock`（空 = 0）。
4. **自检**：保存时若「上限 > 0 且 小于下限」→ 拦下并提示，避免误填。

> 后端、数据库**未改动**，无需重新编译后端；老板端为静态页面，**刷新即生效**（Ctrl+F5）。
> **EXE 无需重打**（本次未动桌面壳与收银端）。

---

## 三、实测验证（本机 API）

| 步骤 | 结果 |
|------|------|
| 读取商品 127 现值 | `min_stock=0 / max_stock=0` |
| `PUT /products/127 {minStock:10, maxStock:200}` | 200 / code 0 ✅ |

| 恢复原值 | 200，回读 `0 / 0` ✅ |

---

## 四、你在真实环境的操作

1. 老板端 **Ctrl+F5** 刷新。
2. 商品档案 → 新增商品 / 编辑商品 → 「**库存下限**」「**库存上限**」就地填写。
3. 商品详情弹窗可核对「库存上下限 X ~ Y」。
4. 仓库/采购相关页面的库存预警与 AI 补货建议会读取这两个值（0 = 不参与预警）。
