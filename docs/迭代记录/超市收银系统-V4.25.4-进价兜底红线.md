# 超市收银系统 V4.25.4 — 进价作为改价/折扣的最终兜底红线

> 来源：老板补充规则（2026-09-13）
> **「如果商品信息没有设置最低价和最低折扣，进价是最后的兜底，不能低于进价销售。」**

---

## 一、红线规则（V4.25.4 定稿）

商品可有两条线，**进价永远是最后底线**，三者取**最严**：

| 层级 | 来源 | 说明 |
|------|------|------|
| ① 最低卖价 | `products.min_price` | 商品档案显式设置（绝对值） |
| ② 最低卖价兜底 | 售价 × 0.6 | 未设 `min_price` 时启用 |
| ③ **进价兜底（最终）** | `supplier_product_prices` 最新进价 | **任何情况下折后单价不得低于进价** |

**生效公式**：
```
改价下限 = 折后价下限 = max( ① 或 ② , ③ 最新进价 )
```

折扣另受「最低折扣率 `min_discount_rate`」约束（已设时，折扣不得低于它）。

**越线处理**：普通收银员**直接拒绝**并给出准确中文提示；店长（`pos.emergency.manual`）可放行，**必写留痕**。

> 说明：本规则只约束**收银端改价 / 单品折扣 / 整单折扣**通道；低价促销仍走「促销活动」模块（既有约定）。

## 二、实现位置

| 层 | 文件 | 改动 |
|----|------|------|
| 服务端（权威） | `backend/src/modules/sales.module.ts` | ① 行商品查询附带最新进价 `cost_price`；② 改价分支红线改 `max(最低卖价线, 进价)`，拒绝文案区分「低于进价」与「低于最低售价」；③ 单品折扣分支同样加进价；④ 整单折扣逐行红线加进价 |
| 价目表下发 | `backend/src/modules/pos.module.ts` | `minPrice` 改为服务端算好的红线价 `GREATEST(最低卖价线, 最新进价)`（**只下发合成值，不暴露进价本身**） |
| 收银端提示 | `backend/public/pwa/cashier.js` | 改价/折扣弹窗文案补充「未设最低卖价时按进价兜底」；版本号 V4.25.4 |
| 商品档案 | `frontend-web/screens/products.js` | 「最低卖价 / 最低折扣」placeholder 改为「按进价兜底」；详情弹窗显示兜底说明与进价；保存时若最低卖价 < 进价给出提示 |
| 缓存版本 | `backend/public/pwa/sw.js` | `pwa-shell-v69` |
| EXE 版本 | `frontend-desktop/package.json` | 4.25.4 |

## 三、实测证据（本机）

**造场景**：商品 127（售价 ¥3.30）→ 清空 `min_price`/`min_discount_rate`，临时插入进价 ¥3.00；临时移除超管放行权，用无放行权身份测试。

| 用例 | 结果 |
|------|------|
| 改价 **¥2.50**（> 售价×0.6=1.98，但 < 进价 3.00） | **400 / 50033**：`改价 ¥2.5 低于进价 ¥3（不得低于进价销售；需店长放行）` ✅ 进价兜底生效 |
| 改价 **¥3.20**（≥ 进价） | **201 成功** ✅ |

**恢复与清理**：临时进价记录已删、`min_price` 恢复 1.98、超管放行权已恢复；测试订单与库存流水**已全量清理回滚**（库存 47、批次 15 均恢复 47，无残留测试单）。

## 四、待你在真实环境确认

1. 找个**未设最低卖价**的商品，在收银台按 **P** 改价到低于进价 → 应提示「低于进价，不得低于进价销售」。
2. 用**普通收银员**账号（无店长放行权）验证会被**拒绝**；店长账号则可放行并留痕。
3. 老板端商品档案详情：未设最低卖价时显示「未设 → 按进价兜底（¥X）」。
4. 收银端刷新后版本号 = **V4.25.4**，缓存 `pwa-shell-v69`。
