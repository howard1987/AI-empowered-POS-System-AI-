## 四、远程电子签名（手机充当手写板）★ 用户长期诉求落地
- **表**（064）：`remote_sign_requests`（req_no 6 位取件码唯一、title/person_hint/biz_ref、status 待签字/已签字/已取消/已过期、result_image_path 落 public/signatures 与现场补签同证据链）。
- **后端** `backend/src/modules/remote.sign.ts`（@Controller('sign-remote')，注册进 app.module）：
  - POST /sign-remote 电脑端发起（返回 id+取件码，冲突换码重试）
  - GET /sign-remote/pending 手机端待签字列表（30 分钟未签字自动置已过期）
  - GET /sign-remote?id= 电脑端轮询（已签字回传 dataURL 签字图 + 签字人姓名）
  - POST /sign-remote/:id/submit 手机端提交（saveBase64Image 落盘 + 状态 CAS 防双写；重复提交 50080）
  - POST /sign-remote/:id/cancel 电脑端取消
- **电脑端** `frontend-web/screens/signpad.js`：签字弹窗 padbar 加「📱 手机采集」按钮 → remoteCapture：建请求 → 弹窗内展示取件码与指引 → 2.5s 轮询（10 分钟超时、点取消即终止）→ 收到签字后走既有 `/purchase/signatures/attach`（补签）或 `/purchase/signatures`（预采集）落证据链，流程与本地手写完全一致。补签与预采集两处均已接入；短信确认模式无 padbar 不受影响。
- **闭环证据**：e2e 冒烟 create→pending→submit→poll（dataURL）→ 重复提交 50080 全过，测试数据已清理。
