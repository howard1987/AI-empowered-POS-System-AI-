## 1. 本期范围

登录后直落的**一级全屏收银台**（横屏双栏 / 手机单栏响应式），复用既有底座（离线价目表、/sales/checkout 组合支付+clientRef 幂等、micropay 被扫+轮询、/pos/held 挂单、离线补传队列、打印/钱箱/语音钩子），按评审定稿落地收银台体验层。

## 2. 数据库迁移（079，幂等）

| 变更 | 说明 |
|---|---|
| `products.min_price NUMERIC(10,2)` | 最低售价；NULL 回填 `FLOOR(sell_price*0.6*100)/100`（未删除商品） |
| 设置组「收银台」 | `pos.cashier.new_ui`(默认1 直落开关) / `quick_count`(8) / `stock_hard`(0) / `lock_timeout`(5分钟) / `debounce`(1) |
| 「收银与库存」 | `stock.negative_sales`(默认1)：负库存售卖总开关（仅补默认，尊重已设值） |

## 3. 后端改动

- **/pos/pricebook**：下发新增 `minPrice`、`pinyin`（拼音码，搜索用）；memberPrice 原有
- **GET /pos/stock?ids=**（新）：实时库存批量查询（不入价目表缓存，收银台警示/负库存判定用）
- **POST /pos/promo-preview**（新）：购物车促销预估（复用 applyPromotions），返回 `promoAmount / nextPromo（再买¥X可用最高档满减）/ goodsAmount`
- **/sales/checkout**：
  - 新增 `manualRound` 参数：手动抹零（元），与自动抹零（`pos.round_rule`）叠加；低于最低售价的 `unitPrice` 硬拦，`pos.price.manual` 权限放行并留痕（audit）
  - 负库存销售：`stock.negative_sales=1` 时 FIFO 吃完后差额挂末位批次（V4.13.9 底座已有，本期补默认种子与收银台联动）
- 设置 PUT /settings/:key 复用（收银设置面板与后台设置页同源、留痕）

- 响应式：<900px 单栏（手机形态）

### 4.2 关键行为（对 §13 定稿逐条）
| 定稿 | 实现 |
|---|---|
| §13.10 负库存容错 | `stockHard=0`（默认）：超库存/沽清弹「负库存售卖确认」→ 成交留痕进本班负库存清单（顶栏入口，红点计数）；`stockHard=1` 一律拒绝。全加车路径覆盖（宫格/快捷/联想/扫码/+1/直改） |
| A2 用券入口 | 结算页「选用券」：拉 /coupons/member 未使用券列表，选券预估抵扣（满减/折扣），结账传 couponId 服务端核销 |
| D1 组合支付退款 | 组合=现金+扫码各一笔 sale_payments，退款按通道占比自动拆（后端既有） |
| D3 扫码 90s 转挂起 | micropay 后 90s 定时器：未完成自动入挂起单（金额+行快照+会员），顶栏挂起单查单续付（SUCCESS→恢复购物车快照落单；FAIL/CLOSED→恢复购物车释放）/释放 |
| B4/D2/挂单 | 挂单/取单走 /pos/held（>24h 灰显提示清理 I1）；价格快照：已加行不受后续调价影响（A4） |
| D4 离线收银 | 断网黄条「离线收银模式」：现金记账入 pwa_queue（clientRef 幂等），联网自动补传（复用全局队列+online 事件）；扫码/券/促销预览离线不可用并明示 |
| F2 锁屏 | 闲置 N 分钟自动锁（设置可配 0=不锁）；工号+密码解锁（复用 /auth/login）；连错 5 次锁 5 分钟；锁屏期间购物车/挂单/设备原样保留；离线提示需联网解锁 |
| I3 弹窗与扫码 | 全局 HID 收码监听：弹窗打开或输入框聚焦时暂停；同码 2 秒防抖+撤销条（设置可关） |
| E1 弹箱失败 | 收现自动弹箱（PwaReceipt.kickDrawer / PwaPrinters 网口联动），失败 toast 明示「手动开箱（已留痕）」 |
| 最低售价 | 改价低于 minPrice：无权限直接拒绝；有 pos.price.manual 确认放行（服务端同样硬拦+留痕，双保险） |
| H3 回退开关 | `pos.cashier.new_ui=0` → 登录落旧「作业-收银」；退出收银台本会话不再直落（sessionStorage），重新登录恢复直落 |

### 4.3 通道枚举安全
`sale_payments.channel` 为 `pay_channel_t` 枚举：扫码通道按付款码前缀推导（10~15→微信 / 25~30→支付宝，与网关 detectChannel 同规则），绝不下发「扫码」等非法枚举值。

### 6.1 开发期抓出的真 bug（已修）
1. `window.ME` 引用错误：app.js 的 `ME` 是顶层 `let`（不在 window 上）→ `maybeEnter` 永远早退、`hasPerm` 永远 false。改用全局词法绑定
2. **id 重复 `csLock`**：顶栏按钮与锁屏遮罩同 id → `lockNow()` 永远命中的是按钮，锁屏失效。遮罩改名 `csLockMask`
3. 挂起单「查单续付」顺序颠倒：先落单后恢复购物车 → 空车落单。改为先恢复快照再 finishAfterGateway
4. 抹零浮点：元口径 `%` 有误差 → 改分口径取模
5. 通道兜底「扫码」非法枚举 → 按付款码前缀推导
6. 组合支付付款码输入框注入被合并编辑误删 → 补回
7. 离线判定过窄（只认「网络异常」文案）→ 兼容浏览器原生 fetch 错误（Failed to fetch/Load failed）
8. 组合支付面板 #csPayGo onclick 重复绑定（死代码）→ 去重
