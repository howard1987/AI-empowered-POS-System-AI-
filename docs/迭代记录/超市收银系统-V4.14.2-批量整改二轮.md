## 二、移动端 PWA

### 1. 拍照调摄像头 + 报损照片上传失效（根因两个）
- **报损无效根因**：`handleLossFile` 已定义但从未调用 `bindPhotoPick` → 已补绑定
- **摄像头不弹根因**：隐藏 file input 用 `display:none`，部分安卓 WebView 对 display:none 的 `input.click()` 不传递相机/文件意图 → 新增 `.file-hidden` 视觉隐藏类（index.html），work.js 全部 file input（photoPickButtons 的 Cam/Gal、OCR 的 ivCam/ivFile）统一切换
- **SW 缓存壳升版 v28 → v29**（否则手机端验旧 JS）

### 2. 入库单「通过」弹窗样式 + 已审核单据签名展示
- app.js 新增 `pwaConfirm()` / `pwaPrompt()` 样式化弹窗组件（替代原生 confirm/prompt）；docs.js 的「通过」「驳回」接入（驳回原因必填留痕不变）
- **签名不显示根因**：docs.js 明细模板中根本没有 `#ddSignBox` 容器，签名加载代码 `if (!box) return` 静默跳过 → 模板补「✍️ 电子签名」段（含后补场景：无记录时提示可在移动端/对账现场补签）
- 列名修正：`signature_records` 无 `created_at`（移动 docs.js 与后台 recon.js 均改用 `used_at`）
- 数据链路验证：入库单 #33 等已有 signature_records 记录，bizType=biz_id 匹配正常

## 三、供应商管理

### 1. 变更单 NaN 报错修复
- 根因：`GET /purchase/supplier-changes` 不带 `supplierId` 时 `Number(undefined)=NaN` 直接传 PG int 参数 → `invalid input syntax for type integer: "NaN"`
- 修复：purchase.module.ts 的 supplier-changes 与 /fees 两处 `Number(x) || 0`；前端打开弹窗即加载记录列表（不带参数）正是触发场景

### 2. 供应商变更记录表格（列表页底部新卡）
- `#chgList`：单号/行数/原→新供应商/原因/操作人/时间 + 「明细」弹窗（逐行 原进价→新进价、原售价→新售价、供应关系、removedSuppliers 清除名单）
- 10 条/页翻页；提交变更单后自动刷新

### 3. 已产生业务供应商经营方式锁定
- 编辑弹窗：`has_business` 为真时 `#nBiz` disabled + 提示「🔒 已产生业务，经营方式不可改；如需变更请新增同名供应商（编号不同），再用供应商变更单迁移商品」（新增供应商允许同名，编号自增不同）

### 4. 独立供应商选项
- 后端 `createSupplierChange` items 增加 `independent`：删除该商品在其他供应商的 supplier_product_prices 关联（逐条快照进 `removedSuppliers` 留痕）、隐含切换 supplier_default_id 到新供应商 → 商品档案供应商只剩新供应商
- 前端供应关系三态下拉：不变 / 设为主供应商 / 独立供应；提交前 confirmBox 二次确认（红色警示独立供应清除关联）
- 变更明细弹窗展示「独立供应」标签 + 清除关联名单
