# 超市收银系统 V4.9.11 —— 商品建档条码大数据自动填充

日期：2026-09-08　范围：后台商品建档（frontend-web）+ 后端条码查询链路（products.module）+ 设置迁移（db/046）　验证：API 三场景 + 浏览器实机操作 全部通过

## 一、需求背景（用户原话锚点）

> 在商品建档时，输入商品条码后，能否通过大数据查询条码，自动填充"商品名称、单位、售价、保质期、规格"等公开数据，如果不正确，用户手动修改。

## 二、方案设计

**数据源链（逐级兜底）**：

| 优先级 | 数据源 | 说明 |
|---|---|---|
| ① | 本店商品库 | `products` / `product_barcodes` / `product_units` 三表联合命中（主码/辅助码/包装码）；命中即提示"本店已有该条码商品"，防重复建档 |
| ② | mxnzp 在线条码库（国内最全） | 需在系统设置配置 `app_id`/`app_secret`（https://www.mxnzp.com 免费自助申请）；**未配置凭据则静默跳过**，不报错 |
| ③ | Open Food Facts | 全球开放食品库，免 key 始终兜底；优先取中文名 `product_name_zh` |

**核心原则：只预填、不锁定**——查到的字段只填充空位，已填字段一律不覆盖；填错用户可随意改。**保质期各库均无权威数据，刻意不做预填，留人工必填**（避免凭空编造保质期）。

**缓存策略**：本店库命中缓存 1 小时；在线库命中缓存 24 小时——避免同一码反复打外部接口。

## 三、改动清单（逐条落盘）

### 后端

| 文件 | 改动 |
|---|---|
| `src/modules/products.module.ts` | 新增 `GET /products/barcode-lookup/:code`：链式查询 本店库→mxnzp→OpenFoodFacts，返回 `{exists, name, spec, unit, price, source, brand, supplier, shelfLifeDays}`；`barcode.lookup.enable` 设置可整体关闭（关闭时未建档码返回 40404 明确提示）；`guessUnit()` 从规格/品名文本启发式推断基本单位（瓶/袋/盒/罐…，推断不出留空由用户补）；查询失败错误逐源透出（如 `mxnzp: HTTP 403`），便于排查凭据问题 |
| `db/046_barcode_lookup.sql` | 幂等迁移，种入 3 个设置项：`barcode.lookup.enable`（默认 true）、`barcode.lookup.mxnzp.app_id`、`barcode.lookup.mxnzp.app_secret`（默认空=跳过该源）——归组"商品与库存" |

## 五、使用说明

1. **日常建档**：商品中心 → 新建商品 → 输入/扫码枪扫条码 → 约 1 秒内自动带出名称/规格/单位/预估售价 → 核对修改 → 保质期等无权威数据的字段人工填写 → 保存。
2. **开启 mxnzp 国内源**（覆盖面远大于 Open Food Facts，建议开启）：系统设置 → 商品与库存 → 「条码库mxnzp app_id / app_secret」填入凭据（mxnzp.com 免费申请）→ 保存即生效（无需重启）。
3. **关闭该功能**：系统设置 → 「建档条码库自动查询」切为 false。

## 六、已知边界与后续建议

1. **本地化部署的取舍**：条码大数据必须联网查询（本店库离线可用，在线源需外网）。与"本地化部署"不冲突——业务数据/AI 模型全在本地，仅建档时查一次公开条码库；若门店完全不联外网，则本店库命中外的条码退回纯手工建档。
2. 预估售价来自公开库，仅作参考默认值，**以店内实际定价为准**（前端已提示"仅供参考"）。
3. mxnzp 免费额度有限，缓存（24h）已减少重复消耗；后续可加"建档成功后写回本店缓存"，让同名商品二次建档零外呼。
4. 保质期、供应商等字段条码库均无权威数据，维持人工必填，不做猜测预填。
