## 二、① 登录即开班（V4.25.0 核心）

**行为**
- 收银员登录成功后进入收银台时，若当前**无进行中班次**，强制弹出「开班确认框」：
  - **收银员**：只读，自动带出（姓名 + 工号）。
  - **机号**：默认 `POS-01`，可改（本机记忆）。
  - **班次号**：新增字段 `shifts.shift_no`（如 `1` / `A` / `早班`），可填（本机记忆）。
  - **开班备用金**：默认读后台 `pos.cashbox.float_default`（默认 200），**本机记忆上次值优先**。
- **回车即进收银**：备用金 / 机号 / 班次号输入框回车，或点「开班并进入收银台」即开班（POST `/shifts/open`）。
- **退出不显「无开班」**：因登录即开班已保证存在进行中班次，退班向导第 1 步直接走「交接班」，不再出现「当前没有进行中的班次」分支。
- **离线紧急兜底**：登录框提供「网络异常？暂不开班进入」入口（仅应急；正常在线必开班）。
- 同一收银员同时仅一个进行中班次（后端 `50065` 保护）。

**数据结构**：`shifts` 新增 `shift_no VARCHAR(16)`（迁移 094）。

**关键函数**：`cashier.js` 的 `openShiftStart({ fromLogin: true })`（登录触发，强制）/ `openShiftModal`（班次按钮触发，可关闭）；`enter()` 末尾 `await refreshShift()` 后判断。

## 三、② 老板端 bootstrap（与收银端同源）

`frontend-web/app.js` 的 `loginView()` 改造：
- 启动自检 `GET /auth/bootstrap`：
  - **无管理员** → 顶部黄条提示「未检测到管理员，请先创建管理员账号」，自动切到「创建管理员」表单（门店名/工号/姓名/密码），提交 `POST /auth/bootstrap-admin` 后直接登录。
  - **有管理员** → 绿条提示账户线索并**预填工号**，回到登录表单。
- 去掉写死的默认工号 `ADMIN`；提供「创建管理员 / 返回登录」切换链接。
- 与收银端共用同一套后端 bootstrap 接口与「超级管理员」角色绑定逻辑。

## 四、③ 锁屏解锁改用 PIN

`cashier.js` 的 `unlockTry()`：
- 优先 `POST /auth/pin-login`（工号 + PIN 免密）。
- 若返回 `41011 未设置 PIN` → **自动回落** `POST /auth/login`（工号 + 登录密码）。
- 输入占位文案改为「PIN 或 密码解锁」；连续错 5 次锁 5 分钟、离线提示等原逻辑不变。
- 前提：员工已在登录时勾选「记住 PIN」或后台设置过 PIN（`employees.pin_hash`）。

## 五、④ 取单默认本人 + 后台开关

**后端** `pos.module.ts` `GET /pos/held`：
- 新增 `scope=all`（全店所有挂单）。
- `scope` 缺省时读后台开关 **`pos.held.default_scope`**（默认 `mine`），实现「默认本人」。
- `mine=本人` / `shift=本人或本班` / `all=全店`。

**前端** `cashier.js` `takeOrder()`：
- 取单列表顶部新增「范围：本人 / 全店」切换按钮（默认态由后台开关决定，可临时切全店查全店挂单）。
- 取单角标 `refreshHeldBadge`（无 scope）也随默认范围走。

**后台开关**：`pos.held.default_scope`（`收银台` 分组，`enum`，默认 `"mine"`）。老板在「系统设置 → 收银台」改该值即改默认范围。

## 六、⑤ 讲述人拟真语音打包 —— 结论：不可行，维持 piper

**实测结论**（V4.24.1 已验证）：
- Windows「讲述人」自带的拟人语音**只注册到讲述人进程**，不注册到系统的 **SAPI / OneCore** 语音列表。
- Chromium / Electron 内核枚举不到这些语音（`speechSynthesis.getVoices()` 为空），因此**无法在收银台播报中使用**，更无法“下载打包”。
- 即便系统装了第三方 SAPI 语音，也面临分发许可、位数匹配、部署机缺驱动等问题，不适合随程序打包。

**既定方案**：维持 **piper 离线神经语音**（后端 `/tts/synthesize`，模型 `zh_CN-huayan-medium` 已随包部署，完全离线、无需联网、无需系统语音）。收银播报优先走服务端 piper，失败回落浏览器 `speechSynthesis`。不引入讲述人依赖。
