## 二、详细设计

### 2.1 开业初始化简化（`settings.js#loadInitPreview`）

- **目标用户**：门店老板/店长，不需要看懂数据库表名。
- **展示方式**：
  - 顶部红底横幅：危险操作提示 + 始终保留说明。
  - 业务模块卡片网格：每个模块显示「● 模块名」+ 状态标签（有数据 / 暂无数据）+ 一句人话风险说明。
  - 不再显示 `sale_orders 92行` 这类具体表名与行数；模块是否为空通过后端返回的表行数合计判断。
  - 保留绿框「这些档案会保留」清单。
  - 保留「清空范围」单选/复选与确认输入框。
- **模块说明映射**：
  | 模块 | 说明 |
  |------|------|
  | 交易与结算 | 销售单、收款退款、交接班流水、挂单等经营流水会被清空 |
  | 库存与单据 | 入库/退货/盘点/调拨/损耗等库存流水会被清空 |
  | 会员与分红 | 会员账户流水、积分、分红记录等会被清空（会员档案可选保留） |
  | 供应商往来 | 对账单、供应商费用、代销结算等往来记录会被清空 |
  | AI 数据 | AI 识别日志、建议、训练样本等会被清空 |
  | 操作日志 | 系统操作记录、设置变更留痕会被清空 |

### 2.2 授权管理板块顺序（`signatures.js`）

- 页面卡片顺序调整为：
  1. 🖊️ 签字授权（预采集）
  2. 🖥️ 授权设备
  3. 🗂 操作记录
- 底部初始化顺序同步改为 `await drawSigs(); await drawDevices(); await drawRecs();`。

### 2.3 Win11 modern 绿色包

- `frontend-desktop/package.json` 版本由 `4.24.0` → `4.25.2`。
- `npm run build`（backend）重新编译（`device.module.ts` 在 V4.25.1 有改动，src 比 dist 新）。
- `npm run dist:modern`（frontend-desktop）生成：
  - `dist-modern/超市收银系统-4.25.2-x64-portable.exe`（绿色包，复制即用）
  - `dist-modern/超市收银系统-4.25.2-win-x64-setup.exe`（安装包）

## 三、验证清单（真实环境）

1. **启动服务**：运行 `start-dev.bat`，`GET /health` 200。
2. **老板端**：刷新页面 → 进入「系统设置 → 系统初始化」。
   - 开业初始化不再显示具体表名/行数，只显示模块卡片 + 有数据/暂无数据 + 风险说明。
3. **授权管理**：进入「系统 → 授权管理」。
   - 页面顺序：签字授权 → 授权设备 → 操作记录。
   - 操作记录滚动时不再浮动，分页条随容器走。
4. **绿色包**：运行 `dist-modern/超市收银系统-4.25.2-x64-portable.exe`。
   - 首次启动应弹出首启配置向导（或读取已有 `%APPDATA%/超市收银系统/desktop-config.json`）。
   - 配置后端地址后应能正常加载登录页，登录后进入收银台。
5. **看门狗**：若之前 PG 起不来，确认 `runtime-watchdog.mjs` 已指向 `backend/node_modules/@embedded-postgres/windows-x64/native/bin/pg_ctl.exe`，重新跑 `start-dev.bat` 即可。
