## 一、落地内容（V4.15.4 存储方案 → 实施）

### 1. 识别帧保留期自动清理（收益最大）
- 新增 `ai.housekeeping.ts`：启动 90 秒后首跑，此后**每 6 小时一轮**
- 规则：只删 `frame_*.jpg`（识别过程帧）且 mtime 早于保留期；**被 ai_samples 引用的帧永不删**（识别纠正会提升为样本，绝不误删训练资产）；递归遍历兼容按月子目录
- 设置项：**后台设置 → AI → 「识别帧保留天数」**（默认 30，改 0 = 关闭自动清理）
- 效果：识别帧从"无限增长"变为"滚动窗口"，磁盘占用稳定在数 GB 内

### 2. 图片目录外置（冷热分层）
- 环境变量 **AI_UPLOADS_DIR**：指向其他数据盘/NAS（如 `D:\pos-images`），启动时 `/uploads` 静态路由自动跟随；不设置则维持 `backend/public/uploads` 不变
- 启动日志会打印当前图片目录；目录不存在自动创建

### 3. 新图按月分目录
- 统一落盘入口 `common/uploads.ts`（saveUploadImage）：新图一律写入 `uploads/YYYY-MM/`（如 `uploads/2026-08/frame_xxx.jpg`），防单目录文件数爆炸
- 读取统一走 `uploadsFilePath()`（按相对路径拼目录），**历史平铺图片与月目录图片通吃**
- 覆盖点：识别帧（ai.emb / ai.sample-match）、纠正裁剪帧（ai.module）、移动端凭证上传（upload.module）、VL 参考图/样本哈希/数据集导出（读取侧全部改造）

### 4. 验证
- 单元级验证：60 天前自由帧 → 删除 ✓；被样本引用帧 → 保护 ✓；上月目录帧 → 删除 ✓（实测扫描 97 张，误删 0）
- 后端 3100 重启健康 ✓；历史图片静态访问 200 ✓；设置项已入库（AI 组可见）
