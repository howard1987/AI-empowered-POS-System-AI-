# 项目独立打包方案

> 前置：《项目打包勘察报告.md》 ｜ 本方案**仅动构建/配置/部署文件，不改业务逻辑**
> 状态：**待确认** —— 文末 Q1~Q8 确认后实施

## 一、release 目录布局（目标产物）

```
release/
├─ server/                      # 服务端独立包（拷到门店服务器即可跑）
│  ├─ dist/                     #   tsc 编译产物（含 scripts/init-db.js）
│  ├─ public/                   #   静态站（含 admin/ pos/ 由构建脚本注入，见下）
│  ├─ node_modules/             #   仅生产依赖（--omit=dev，离线可用）
│  ├─ db/                       #   幂等迁移 0xx_*.sql
│  ├─ .env.example              #   PORT/DATABASE_URL/JWT_SECRET/HTTPS_PORT/AI_UPLOADS_DIR 模板
│  ├─ start-server.bat          #   读 .env 启动 node dist/main.js（PORT=3100）
│  └─ README-SERVER.txt         #   首启三步：配 .env → init:db → start
├─ admin/                       # = frontend-web 产物（构建脚本同步进 server/public/admin，访问 /admin）
├─ pos-web/                     # = backend/public/pwa 产物（同步进 server/public/pos，访问 /pos）
├─ pos-desktop/                 # EXE 四件套：modern setup/portable + win7 setup/portable
├─ build-all.ps1                # 一键：清理 → 编译服务端 → 装配 admin/pos-web → 打包 EXE → 汇总 release/
└─ README_DEPLOY.md             # 部署总说明（服务器/收银机/平板三段式）
```

**托管原理**（勘察报告 §4）：不改 `main.ts`——服务端 `useStaticAssets(public)` 自动挂载；
`build-all` 把 `admin/`、`pos/` 同步进 `release/server/public/` 子目录，`/admin`、`/pos` 即刻生效，同源免 CORS。

## 二、构建脚本职责（build-all.ps1）

1. **前置清理**（见第四节清单，首次运行时列单确认）
2. 服务端：`npm run build`（tsc）→ `npm prune --omit=dev` 的依赖拷入 `release/server/`（连同 `public/ db/ package.json`）
3. 后台管理端：`frontend-web` 整目录同步到 `release/server/public/admin`（剔除 `.playwright-cli` 等）
4. 收银 Web 端：`backend/public/pwa` 同步到 `release/server/public/pos`（SW/manifest 相对路径自动适配子目录）
5. 桌面端：`ELECTRON_MIRROR=npmmirror` 依次 `dist:modern`、`dist:win7` → EXE 拷入 `release/pos-desktop/`
6. 生成 `start-server.bat`、`.env.example`、`README_DEPLOY.md`；校验 `/health` 文件存在性并打印产物清单

## 三、外部可配置（不硬编码）

## 五、风险与说明

- **旧入口兼容**：/pwa→/pos 后，已"添加到主屏幕"的设备旧入口仍指 /pwa——方案默认**保留 /pwa 原样**（新旧并存）过渡，不强制迁移（待 Q1 确认）。
- 离线部署：release/server 自带 node_modules，目标机仅需 Node ≥20 LTS（建议 22）+ PostgreSQL；**不依赖 Redis**。
- EXE 无签名 → SmartScreen 提示；Win7 轨 ia32 在 64 位 Win11 上亦可运行（已实测可启动）。
- 平板摄像头/PWA 安装必须 HTTPS（自带 :3443 自签方案，README 写清信任步骤）。

## 七、确认结论与实施结果（2026-09-12 已实施 ✅）

| # | 用户确认 | 实施结果 |
|---|---|---|
| Q1 | **收银 Web 挂 `/pwa`**（不新增 /pos） | 沿用原路径，零迁移成本；`release/server/public/pwa/` ✔ |
| Q2 | **`/admin` 挂 `frontend-web` 24 屏完整后台，随包** | `release/server/public/admin/` 由构建同步 ✔；初版骨架页不下发（改为运维入口页）；boss/member/display 照常随包 ✔ |
| Q3 | **允许** | `api.js` 兜底改为 `localStorage.api_base \|\| window.__API_BASE__ \|\| location.origin`；`server.mjs` 独立部署时注入 `__API_BASE__` ✔ |
| Q4 | **内嵌便携 PG** | `release/server/pg/` + `scripts/server-up.mjs`（释放→initdb→启动→迁移→拉起后端，ASCII 路径自愈）✔ |
| Q5 | **保留 `.md`，其余清理，不归档** | 根目录 60+ 诊断产物、`.edge_tmp_*`、旧回归脚本/png、frontend-desktop 旧 dist 与 smoke 脚本、旧 4.21.2 EXE、`.playwright-cli` 缓存全部删除；全部 `.md` 与运行数据（logs/certs/.runtime/uploads）保留 ✔ |
| Q6 | **先 bat + README 附服务化步骤** | `start-server.bat` / `stop-server.bat` + README 第五节 NSSM/计划任务 ✔ |
| Q7 | **EXE 先只做 Windows 11** | 仅 `dist:modern`；Win7 轨由 `build-all.ps1 -Win7` 待定稿后执行 ✔ |
| Q8 | **做** | build-all 内置冒烟：临时端口 + 临时数据目录起真实服务，校验 `/health` + ADMIN 登录 + `/admin/` + `/pwa/` ✔ |

**方案结构的一处调整**：原计划在 release 下平铺 `admin/`、`pos-web/` 两份目录再同步；实际改为**直接产在 `server/public/admin`、`server/public/pwa`**（收银端本就挂在 `/pwa`，无需另存一份），避免双份产物漂移。构建模板统一放源码 `超市收银系统-初版代码/deploy/`，`build-all.ps1` 会把自身与 `README_DEPLOY.md` 复制进 `release/`，发布包自描述。

**详细实施与踩坑记录见《超市收银系统-V4.23.0-独立打包与部署工程.md》。**
