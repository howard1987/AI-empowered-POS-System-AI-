# 超市收银系统 · 未完成模块 / 完成度不足 / 界面原型差距分析与改进方案

> 分析基准：设计方案 V4.8.22、《超市收银系统-界面原型.html》（24 屏）、《超市收银系统-数据库建表SQL-v1.1.sql》（74 表）、初版代码（backend 16 模块 + frontend-web 19 屏 + frontend-desktop + frontend-h5，564 项真库断言全过）
> 生成日期：2026-09-05

## 一、总体结论

1. **核心业务闭环已完成**：分红引擎、FIFO 进销存、购销对账、促销、会员、收银、权限等设计第 5~7、10 章已全量落地，564 断言通过，Win10/11 + Win7 双安装包就绪。
2. **数据库先行、逻辑缺失**：74 张表全部建好（与 v1.1 SQL 一致），但其中 **21 张表在 backend 代码中零引用**——对应模块"有表无逻辑"。
3. **界面原型 24 屏 → 已落地 18 屏**：完全缺失的 6 屏（采购订单、智能营销、员工移动端、智能决策中心、老板移动端、顾客扫码购）已全部补齐，剩 1 屏（小程序商城）+ 部分缺失 8 屏。
4. **最大缺口集中在三期方向**：移动端（员工 PWA / 老板端 / 小程序）、AI 真引擎、在线业务——与设计方案 15.6 的"尚待实现"清单吻合，但其中**采购订单、盘点/报损/调拨、智能营销、联营对账属"设计已定、表已建"却未排进 P0 清单**，容易被遗漏。

## 五、改进方案（按优先级 · 最小实现优先）

### P0 上线前必做（工作量 1-2 周）

1. **语音播报**（设计 P0，收银体验关键）
   - 方案：桌面 renderer 用 Web Speech API `speechSynthesis`（Electron 内置，零依赖），结账/找零/会员识别 3 处触发；无网络也可用系统 TTS。
2. **采购订单 → 入库单闭环**（表已建，补接口+一屏）
   - 后端：新增 `GET/POST /purchase/orders`、`POST /purchase/orders/:id/approve`（复用 `purchase_orders` 表，状态机 草稿→待审批→已下单→到货中→已完成）。
   - 前端：Web 新增 `screens/po.js`（对照原型 #19：建议单表格 + 状态筛选 + PO→入库单穿透）。
