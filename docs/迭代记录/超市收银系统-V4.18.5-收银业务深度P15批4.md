## 二、后端改动

### `pos.module.ts`
- `GET /pos/refund-lookup?no=`：按单号查已完成订单 → 行明细带 `qty / refunded / refundable`（已退占用口径 = `已退款/待审核/创建中`，与 refund.create 一致）；**挂账/赊账单拒退**（P2-M8 冲减口径）；返回 `refundLimit = sales.refund.limit`（免审限额，默认 200）

### `pay.gateway.ts`
- `GET /pay/pending`：本店近 24h `PENDING` 网关流水清单（收银台启动查漏，页面重开不丢卡单）
- `POST /pay/txn/:outTradeNo/abandon`：查单确认未付后人工释放，`PENDING → FAIL/ABANDONED`，fail_msg「收银台确认未支付，人工释放挂起」，写 audit

## 三、前端改动（`cashier.js`）

- 顶栏新「**退货**」按钮（`csRefund`）→ `openRefund()`：
  1. `pwaPrompt` 输小票条码 / GD 单号 → `refund-lookup` 带出原单（头信息含支付额/时间/会员/免审限额）
  2. 行清单：勾选联动数量（取消勾=0，勾选=可退数），数量上限=可退
  3. 原因下拉必选（质量问题/顾客反悔/错扫多扫/规格不符/临期处理/其他→补说明弹窗）
  4. `pwaConfirm` 展示预估退款（服务端精确分摊整单优惠）；**超限额提示转审核路径**（店长有 `sales.refund.audit` 则提示可即时放行）
  5. `POST /refunds {orderId, items, reason, restock:true}` → `待审核`时店长可当场 `/refunds/:id/audit` 放行；成功 toast 带退款单号，`refreshStock()`
- **挂起单服务端合并**：启动拉 `/pay/pending`，与本地挂起单按 outTradeNo 去重合并，`serverOnly` 行标黄「服务端卡单（本机无商品明细）」；查单（`/pay/txn/:no`）已付自动续流程 / 未付可释放（确认后 abandon），角标同步刷新
- **语音**：`addToCart` 报价（会员价优先）+ 库存偏低提醒；收款播报 `PwaTTS.cash(payable, channel)`；全链路 try 包裹，headless/无语音设备静默

### 缺陷修复（CDP 回归抓出）
- `$('#csRefund').onclick = openRefund` 把点击 **Event 对象**当 `prefillNo` 传入（truthy）→ 跳过输入框直接查 `[object MouseEvent]` 报「未找到该小票号」；改为 `() => openRefund()`，SW 升 v51
