# V5.0.0 · 连锁版改造（大版本）

> 定位：从「单店收银系统」升级为「**总部 + 门店节点**的连锁系统」。
> 总原则（贯穿全部批次）：**单店部署 chainEnabled=false 时零回归**——新表空、新键不接线、新逻辑全部有总部/连锁前置判断，单店行为与 V4.26.x 完全一致。
> 方案全文：项目根 `超市收银系统-连锁版改造方案.md`（8 章 3800+ 行）；决策与陷阱沉淀：`.workbuddy/memory/连锁版方案-关键决策.md`。

---

## 一、架构总览（五个拍板）

1. **总部中心 + 门店本地节点** 星型拓扑：门店主动出站推送（上行），总部经 `sync_changes` 下发（下行）；**否决**门店直连总部库（违背离线可用约束）。
2. **不分库分表**：单库承载，靠 `store_id` 隔离 + 数据范围（`roles.data_scope`）控权。
3. **权威方唯一**：商品主档 / 会员资产 = **总部**；销售单 / 库存 = **门店 append-only**。
4. `sync_outbox` 与业务写**同事务入队**（绝不丢件）；时序用 HLC `(biz_ts, seq, node_code)`，不用纯 `created_at`。
5. **单店降级运行永远可用**：断网门店照常收银，恢复后自动补传。

同步安全三件套：`Authorization: Node <code>:<token>` 节点鉴权 + `x-sync-ts`(±300s) + `x-sync-nonce` 一次性防重放（40100）。

## 三、P2 连锁增强（批次 1~7，迁移 112~115）

| 批次 | 交付 |
|---|---|
| P2-1 断网挂账 | 门店断网时会员余额扣款落 `member_offline_credits` OFF 凭证，恢复后自动清算（settled/rejected）；孤儿扣款 3 天 SLA 自动冲正（RV 幂等）；`member.offline.*` 三键默认关 |
| P2-2 拒付补付 | 挂账清算被总部拒付 → 门店向会员收现金/微信/支付宝结清（`/member-offline-credits/pay`，CAS 防双重结清）；NodeGuard nonce 一次性防重放 + 逐批明细链（`sync_sale_batches` + SyncReconJob 逐批对账）+ 总部销售日物化视图 |
| P2-3 组合支付 | 会员余额不足 → **组合支付**（余额抵一部分 + 现金/微信/扫码当场结清），**会员赊账通道停用**（40003）；防双扣守卫（gatewayTxnId，重试落单绝不重扫码）；H5 余额预检；大客户 B2B 应收/断网挂账/历史欠款销账不在停用范围 |
| P2-4 临期转退货 | 临期预警批次复选 → 一键按供应商分桶生成退货单（钉批次不走 FIFO），审核自动闭环（扣批/售罄/流水/处置） |
| P2-5 促销投放 | 总部促销 `publish/unpublish` 下发指定门店（幂等键 `hq_promo_id`），门店 applyChange 特判防覆盖自建促销，收银端零改动自动生效 |
| P2-6 设置下发 | 总部对门店级设置键「下发/恢复默认」（批量 upsert `store_settings` + 逐店 enqueueDown）；hq 键保存自动全连锁下发；前端设置页「⤓ 下发」弹窗 |
| P2-7 区域汇总 | `stores.region` + `/hq/reports/region-summary`（分区/店数/单量/销售/毛利+环比）+ 报表页 tab |

## 四、P3 本轮功能（迁移 116，sw v77）

### ④a 大客户专属价/批发价 → 总部审批流，提货在门店，总部对账核销

- **价申请**：门店在大客户页新增「📨 价申请」tab 提交（客户归属校验、申请价 ≤ 零售价×1.2、同客户同商品 pending 去重），单号 `SQ-yyyymmdd-xxxx`，快照零售/批发价留痕。
- **总部审批**：通过 → `big_customer_prices` 自动生效（生效期顺延防唯一冲突）；驳回 → 仅留备注，价目不动。
- **连锁守卫**：门店直改专属价 40300「请改走价申请」；总部直设放行。
- **批发价兜底**：无专属价时按 `products.wholesale_price` 计价（低于零售才生效），防双重折扣。
- **提货在门店**：大客户团购单经同步层上行总部记账（明细含批次成本链 `sync_sale_batches`）。
- **对账核销**：`GET /hq/recon/summary` 按门店汇总期内销售/成本/毛利/会员消费额/大客户消费额/赊账未收；`POST /hq/recon/settle` 生成核销单 `HX-yyyymmdd-xxxx`（默认=期内毛利可改）+ 核销历史。会员消费 + 大客户消费由此闭环。

### ④b 每日净利 + 自动分红（分红口径补全）

- **门店硬消耗设置**：设置页新增「门店硬消耗（分红口径）」组（月度元）：`store.cost.rent/utility/depreciation/other`，支持总部统一下发 / 门店自设（`store_settings` 覆盖 → system 默认）。
- **每日净利**：日结快照固化后自动 `hard_cost_daily = 月硬消耗 ÷ 当月天数`、`net_profit = profit_total − hard_cost_daily`（迁移回填存量 `net_profit=profit_total`）；无快照时实时计算兜底。
- **自动分红**：`dividend.auto.enabled`（默认开）+ 每日 02:35 定时任务，按**昨日净利 × dividend.ratio** 计提分红池（biz_date 幂等、净亏跳过）；补跑端点 `POST /dividend/auto/run`。
- **利润看板**：分红页新增「每日利润与自动分红」卡——毛利 / 硬消耗日摊 / 净利（含分红池预估）/ 自动分红开关四 KPI（`GET /dividend/profit-breakdown`）。

### 顺手修复（存量 bug）

- `sales.jobs.ts` 退货/作废回冲批次状态误写 `'正常'`（枚举里没有，触发即 500）→ 改 `'在库'`。
