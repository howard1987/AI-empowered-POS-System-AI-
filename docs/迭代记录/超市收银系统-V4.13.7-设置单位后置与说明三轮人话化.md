# 超市收银系统 V4.13.7 — 设置单位后置 + 说明三轮人话化

> 日期：2026-09-09 ｜ 前置：V4.13.6（053）｜ 迁移：`backend/db/054_setting_units_clarify.sql`（幂等）

## 一、需求（用户截图反馈两项）

1. **单位错位**：部分设置说明列只有单位（如「有效消费窗口天数」说明=天、「年化橙色/红色预警」说明=%）——单位应显示在「当前值」后面，说明列应显示真正的说明文字。
2. **剩余黑话**：说明中仍有看不懂的，如「分红上限（dividend.cap_rate）的累计口径」。

## 二、改动清单

### 2.1 054 迁移（幂等，可重放）

| 块 | 内容 |
|---|---|
| ① 加列 | `ALTER TABLE system_settings ADD COLUMN IF NOT EXISTS unit VARCHAR(16)` |
| ② 单位填充 | 数字型 45 项：天×13、元×12、%×4、小时×3、秒×3、次×2、件/单/张/积分/km/kg 各 1 |
| ③ 名称去重 | 名称里的单位后缀去掉 18 项（「单笔充值上限(元)」→「单笔充值上限」，单位只在值后展示） |
| ④ 黑话清零 | ④-1 cap_mode 枚举 label 去「离散/连续」（值 A/B 不变，读端零影响）；④-2 「终身封顶率R」→「分红终身封顶比例」；④-3 纯单位 7 项补真说明；④-4 键名引用/工程口径改白话共 17 项 remark |

### 2.2 后端（settings.module.ts）

- `list()` SELECT 增加 `unit` 列，API 随行返回。

### 2.3 前端（frontend-web/screens/settings.js）

- `control()`：数字型输入框后拼 `<span class="set-unit">单位</span>`；
- `fmtDefault()`：数字型默认值后拼单位（如 `30 天`）；
- CSS 新增 `.set-unit`（灰字小号，紧跟输入框）。

## 三、效果对照（财务管理组示例）

| 设置项 | 改前说明 | 改后当前值 | 改后说明 |
|---|---|---|---|
| 有效消费窗口天数 | 天 | `30 天` | 「窗口内累计消费」的统计天数范围 |
| 年化橙色预警 | % | `25 %` | 分红年化达到该比例时橙色预警，提醒关注分红支出 |
| 上限口径 | 分红上限（dividend.cap_rate）的累计口径 | 下拉「按累计充值金额封顶」 | 终身分红封顶按什么口径累计：累计充值金额，或分红发放次数 |
| 终身封顶率R | 累计分红 ≤ 净充值 × 该比例… | — | 改名「分红终身封顶比例」，说明：每位会员累计领的分红 ≤ 其累计充值 × 该比例；达到封顶后新分红只发积分，不再发现金 |
| 审计日志保留期 | 天 | `365 天` | 审计日志保留天数，到期自动归档清理 |
