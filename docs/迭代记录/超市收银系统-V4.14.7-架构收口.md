## 1. RV-01 按分计算（sales.module.ts + refund.module.ts）

**改法**：金额链路全程整数分运算，落库前回除为元：
- **行金额**：单价先取整分 `toCents(unitPrice)` × 数量后取整（包装定价行金额同样按分）；行优惠、行成本同口径。
- **应收链**：货值(分) − 促销 − 券 → **抹零改为对「分单位」取余**（角=10分/5角=50分/元=100分，整数取余零尾差）→ + 配送费；应急上限比对按分。
- **混合支付**：每通道 `toCents(pay.amount)`；「自动付清」余额通道 = 应收分 − 已付分（末通道精确吃尾差）；余额**本金/赠送拆分**按分（比例×总额取整，封顶本金余额）；积分兑换按元换算不变；`paidCents !== payableCents` 逐分比对替代原 toCents 二次转换。
- **通道校验**：`amount_cents` 与支付分直接相等比对（40902 文案同前）。
- **退款**：`calcRows` 行退款/整单优惠回冲全程按分（尾差进最后一行，分母防 0 改为 1 分）；支付原路退逐渠道取整分、末渠道 = 退款总额 − 已分摊；余额回退本金/赠送按原流水比例按分。

**口径说明**：等级折扣单价（r2 后的展示单价）作为计价输入不变；本改动消除的是**累计与拆分**环节的浮点漂移，不改变正常场景下的分币结果。

## 3. RV-07 站内提醒 + 铃铛红点

- **061 迁移**：`notices` 表（store_id/kind/title/detail JSONB/perm 收件权限点/batch_key 去重键/read_by 已读数组，部分唯一索引保证同批次幂等）+ `daily_settlement.stock_drift_fixed`。
- **触发点**：`finance.recon.ts` 账单对账 summarize 后，`diff_rows>0 或 reverseRows>0` → `notifyStaff()`（common/notices.ts helper），同批次重复导入不重复提醒。
- **端点**：`GET /finance/notices`（按员工 perms 匹配收件权限点，最新 50 条，含 read 标记）、`GET /finance/notices/unread`（红点数）、`POST /finance/notices/:id/read`（read_by 追加个人，各自独立已读）。
- **前端**：顶栏铃铛 🔔 + 红色未读角标（60s 轮询+路由刷新），下拉面板列表，点击标记已读；对账差异提醒点击跳转「对账结算」页。
- **实测**：插入提醒 → 未读 1 → 列表含明细 → 标记已读 → 未读 0；权限点过滤按 JWT perms。
