> 报告日期：2026-09-11　|　覆盖范围：第一版设计方案（V4.8.22 基线）→ V4.18.5（P15 批4）　|　环境：dev 联调库（PG 54329 / 后端 3100），API 层实测

## 一、报告说明

- **梳理方法**：以《超市收银系统设计方案》（含 §14.2 补缺清单、§15.6 尚待实现表）与《收银端专项设计方案》（§5 功能总表 / §9 分期 / §12 银豹借鉴 / §13 评审 32 项定稿）为"承诺基线"，逐项对照代码与版本文档（V4.9.8 → V4.18.5 共 50+ 版）核实落地状态。
- **测试方法**：编写一次性渗透脚本对运行中的后端做 API 层实测——认证伪造、低权账号负向授权、资金安全（改价/超退/超上限/红线）、SQL/类型注入、幂等重放、CORS/信息泄露、登录爆破锁，共 42 项；初测 35 项 → 逐项复核（发现测试号权限过宽等用例误差）→ 补造低权账号终测，全部结论以最终复核为准。
- **用户豁免项**：真机/外设/性能类测试不在本报告遗留清单内（按约定统一联动测试）。

## 五、结论与建议

1. **安全结论：未发现可利用漏洞。** 认证、授权、资金红线、防超退、幂等、注入防护、爆破锁全部实测有效；4 个 OBSERVE 项均为设计口径/健壮性建议，非漏洞。
2. **上线前必办**：清理 E2E01 等测试账号权限为最小集（本报告唯一中等级风险项）。
3. **功能收口建议**：§3.1 的 10 项中，**分单（#1）与部分支付两态（#2）**是仅有的两个"承诺了且完全没做"的业务能力，建议列为 P15.5 或随 P16 一并补齐；其余为体验增强。
4. **P16 依赖**：部署定稿（PC=EXE）依赖 C 端演进，是当前最大的整体缺口，建议尽快排期。
5. 测试痕迹与账号处理已执行（PTLOW 停用）；渗透脚本为一次性已删除，全程可按本报告 §4 用例复现。

*附：初测 35 项 → 复核修正说明。初测 7 项 FAIL 全部归因：①E2E01 权限过宽（6 项）；②预期错误码与实际不同（50031 vs 40902，拒绝本身正确）；③幂等用例数据竞争（复核通过）；④"重复退货"实为合法的第二笔部分退。无一项为真实漏洞。*
