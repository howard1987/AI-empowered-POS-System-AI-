> 版本：应用版本 4.22.2 → **4.22.3**（严格递增）；`frontend-desktop/package.json` + 收银台 `.cs-ver` 同步

## 一、问题（用户报障）

| # | 现象 | 影响 |
|---|------|------|
| 1 | 登录界面红框（登录卡片）之外的东西都不要；**登录前不要置顶在最前面** | 登录页铺满整屏且压住其他程序，老板开机后想先干别的干不了 |
| 2 | 收银端要**全屏显示**，但**允许切换其他程序** | 一轮加的置顶（screen-saver）让收银台永远压在最上层，Alt+Tab/任务栏都切不走 |
| 3 | 购物车右侧与屏幕**没有留白过渡**，直接占满右侧屏幕 | 白卡顶到屏幕右缘，宽屏上被拉长，观感生硬 |
| 4 | 后台**有挂单不允许退出**（收银端） | 挂单没处理完就离场，易丢单/串单 |
| 5 | 登录页允许**记住工号和密码** + 密码框**小眼睛** | 专用收银机每天开机重复输密码 |

## 二、根因

### 问题 1/2：一轮用「置顶」解决任务栏，代价是抢焦点

一轮为压住 Win11 任务栏用了 `setAlwaysOnTop(true, 'screen-saver')`（Electron 最高置顶层级）。
副作用是窗口**永远压在其他程序之上**，Alt+Tab / 点任务栏都切不走；
且窗口开机即全屏 kiosk，登录页也只能铺满整屏（`LOGIN` 没有独立形态）。

### 问题 3：右栏为「满屏白卡」实现，与高保真原型不一致

高保真原型（`超市收银系统-P14收银台高保真原型.html`）右栏是 `max-width:560px` + 页面底色 + 内容左右 12px 内距；
而 `cashier.js` 实现成 `#csRight{flex:1;background:var(--card);max-width:46%}`——**白卡铺到屏幕右缘、内部行只有 14px 内距**，
1366 以上显示器上被拉得很长，右侧毫无过渡。

### 问题 4：退出只做了「确认」，没有业务前置校验

`CashierShell.exit()` 直接 confirm → logout。另发现隐藏缺陷：`$('#csExit').onclick = exit;`
把 click 事件对象当 `silent` 参数传进 `exit(silent)`（truthy）→ **确认框被整段跳过**（点一下就直接退出登录）。

### 问题 5：登录页无记住能力

`app.js` 登录流程只用 `#lgNo/#lgPw` 的值直接调 `/auth/login`，没有本机记忆；密码框无可见性切换。

## 三、修复（V4.22.3）

### 1. 登录态 / 收银态窗口形态分离（`frontend-desktop/src/main.js` + `preload.js` + `app.js`）

新增两条窗口形态与一条切换通道：

| 形态 | 时机 | 行为 |
|------|------|------|
| `login`（`applyLoginMode` → `applyWindowedMode(460×620)`） | 启动、退出登录、断连错误页 | 卡片大小、中心居中（按 `workArea`，**不压任务栏**）、**不置顶**、任务栏有图标、可拖拽可关闭 |
| `cashier`（`applyCashierMode` → `applyKiosk`） | 登录成功 / 会话恢复（`showMain()`） | `setBounds(display.bounds)` + `setKiosk(true)` **盖任务栏**，但 **`setAlwaysOnTop(false)`** → Alt+Tab / 任务栏切换其他程序完全正常 |

- 渲染层通道：`DesktopShell.setShellMode('cashier'|'login')` → 主进程 `pos:shell-mode`；
  `app.js` 的 `showMain()` 切收银态、`logout()` 切登录态（两处接线，一条通道，浏览器/手机端无壳调用自动 no-op）。
- `close` 拦截改用**运行期** `kioskOn`（旧代码用常量 `KIKS`，切回登录小窗后仍会拦关闭，Alt+F4 无效）。
- 配置向导 / 断连错误页会临时把主窗切回普通窗口（`applyWindowedMode`，错误页 720×560），关闭后按 `shellMode` 恢复。
- **坑（实测抓到）**：`setKiosk(false)` 是**异步**的，紧接着 `setBounds` 会被随后的全屏恢复覆盖 →
  退出收银台后登录页仍是全屏。修法：等 `leave-full-screen` 事件再摆位 + 400ms/1000ms 两级兜底重摆。
- 新增窗口自检通道 `DesktopShell.shellState()`（`pos:shell-state`）：返回 `shellMode/kioskOn/isKiosk/isFullScreen/bounds/workArea`，
  供现场排查与自动化实测断言。

### 2. 登录页记住工号密码 + 小眼睛（`backend/public/pwa/index.html` + `app.js`）

- 密码框外包 `.pw-wrap` + 右侧 `#lgEye`（👁/🙈），点击切换 `password ⇄ text`，不改变输入值。
- 新增「记住工号和密码」`#lgRemember`：**登录成功后才落盘**（不会存下打错的工号/密码）；
  未勾选 / 中途取消勾选 → 立即清除本机记录。存储键 `pwa_login_remember`，密码做 UTF-8 安全的 base64 编码（**非加密**，仅防肉眼直读）。
- 回填规则：上次勾选过 → 自动填工号+密码且勾选保持；桌面端首次默认**勾选**（专用收银机），浏览器/手机端首次默认不勾选。
- 桌面端登录窗留白处可拖动窗口（`-webkit-app-region:drag`，卡片/输入/按钮 no-drag）。

### 3. 收银台右栏留白（`cashier.js` 样式）

- 主区四周留白：`#csMain{padding:0 12px 12px}` → 购物车不再顶到屏幕右缘（左右对称、两栏底部对齐）。
- 右栏限宽：`#csRight{max-width:min(46%,600px)}`（对齐高保真原型），宽屏不再被拉满；`#csLeft/#csRight` 底部 12px 圆角。

### 4. 有挂单禁止退出 + 退出按钮传参修复（`cashier.js`）

- 新增 `heldPendingCount()`（`GET /pos/held` 长度）；`exit()` 先校验：
  - **EXE 桌面端**（真退出登录）：>0 笔 → `toast("还有 N 笔挂单未处理：请先「取单」结账或在取单列表删除后再退出")` 并**中止退出**；
  - 浏览器/手机端：只提示不拦（退出只是回工作台，硬拦会被**别人的挂单**锁死）。
  - 查询失败（断网/离线）→ 视为 0 放行，避免把收银员困死在收银台。
- 修复 `$('#csExit').onclick = () => exit();`（原写法把 Event 当 `silent`，确认框与本次挂单校验都会被绕过）。

### 5. 其它

## 五、遗留与风险（需现场确认）

1. **任务栏遮挡**不再依赖置顶，而依赖 kiosk 全屏（`bounds = display.bounds`）。实测窗口已覆盖任务栏区域且 `isFullScreen=true`；
   若某些机器「任务栏始终置顶」设置仍让任务栏露出，可在 `applyKiosk` 追加显示期间的兜底重摆（不建议恢复置顶，否则问题 2 复发）。
2. 挂单是**门店级**数据（`GET /pos/held` 不过滤收银员）→ 桌面端退出的拦截对**全店挂单**生效；如需只拦「本人/本班挂单」，需后端加 `held_by/shift_id` 过滤。
3. 「记住密码」为**本机便利**（base64 编码存储，非加密）。公用收银机建议不勾选；后续可升级为「只记工号 + 记住 PIN」方案。
4. 收银态窗口**不置顶**是刻意设计：顾客理论可切到桌面。若需要「全屏 + 不可切走」的强 kiosk 场景，应作为后台开关（`pos.desktop.kiosk_topmost`）而非默认。

1. 重启后台（PG 停止时登录会失败）：`start-dev.bat`；PWA 侧改动是服务器文件，**刷新页面即生效**（收银台左上角确认 `V4.22.3`）。
2. 装新 EXE：`frontend-desktop\dist-modern\超市收银系统-4.22.3-x64-portable.exe`（`main.js/preload.js` 属壳代码，**必须重打包**才生效）。
3. 逐项确认：
   - 开机 → 登录窗只有一张卡片（460×620）、**不置顶**，可 Alt+Tab 去别的程序、可在留白处拖动；
   - 登录 → 收银台全屏（任务栏被盖住），Alt+Tab / 点任务栏可切换其他程序，切回来仍是收银台；
