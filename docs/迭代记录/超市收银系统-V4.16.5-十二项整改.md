## ⑧ 手机采集签字五点整改
- **根因修复**：`remoteCapture(view, box, bizRef, submit)` 实参错位（此前 submit 收到字符串 → "submit is not a function"；bizRef 收到弹窗 DOM → 库里存 "[object Object]" = 手机端「取件码862545·[object Object]」的来历）
- **① 三连采**：PWA SignPad 新增 `openCollect`——预采集场景一次连写 3 遍（进度「第 N/3 遍」），一次提交，后台无需分次发起；补签场景仍单张
- **② 横屏+田字格**：采集板 900×240 建议横屏（尝试 orientation.lock）+ 2字/3字姓名按钮自动分格，每格田字虚线引导；应签人提示 2/3 字时自动选格
- **③ 预览签收/退回**：手机提交 → 状态「待签收」；电脑端轮询到后弹**预览窗**（3 张样本并排+退回次数/原因）→ ✅签收（POST /:id/accept → 走既有 attach/预采集入口落证据链，预采集传 images[] 三张建画像）或 ↩退回重签（POST /:id/return 带原因 → 状态回待签字、attempts+1）；手机端监听退回自动重新采集
- **④ 取消即失效**：电脑端点「取消」→ POST /:id/cancel；手机端采集板每 3~4s 监听，已取消/已过期自动关闭并提示
- **⑤ [object Object]**：即实参错位所致，随根因修复消除
- 后端 remote.sign.ts：submit 支持 images[1..3] 存 result_images jsonb；detail 返回 images[]/attempts/returnNote；新端点 accept/return；重复提交/越状态 CAS 拦截。e2e 六步全过（建请求→三样本→待签收→退回→重提签收→重复拒绝）

## ⑪ 电子秤条码格式设置
- 设置项 `ai.scale.barcode_format`（预设下拉 16 项：无/FWWWWWC/FWWWWWWEEEEEC/FWWWWWWNNNNNC/金额+商品码/双前缀/带小数点锚/单价式/自定义…）+ `ai.scale.custom_format`（自定义模板）
