## 一、扫描结论总览

| 线 | 结论 |
|---|---|
| SQL 注入 | ✅ 干净：全参数化（$1/$2…），动态 `${}` 均为内部常量（READY_STATUS/SQL_ORDER_DONE）、Number 化的 LIMIT、表名白名单（admin.reset 固定数组 + pg_tables 存在性过滤） |
| XSS | ✅ 良好：innerHTML 渲染统一走 esc()；抽查未逃逸命中均为 textContent/toast/confirm 上下文（无注入面） |
| 越权 | ✅ 全局 AuthGuard（APP_GUARD）+ @RequirePerms 权限点；会员端 MemberGuard 与员工 token 互斥（kind 校验双向隔离）；admin.reset 挂 sys.data.backup |
| 文件上传 | ✅ 文件名一律服务端生成（frame_时间戳/sig-时间戳-随机），MIME 白名单（png/jpeg dataURL 校验），无用户可控路径 → 无路径穿越/无 stored XSS |
| 敏感数据 | ✅ 密码/密保答案 bcrypt（cost 10）不落明文；支付 secret AES-256-GCM + 界面脱敏；.env 仅 example 入目录；JWT 12h 过期 |
| 认证 | ⚠️→✅ 员工端登录/密保找回**无爆破防护**（本轮已修，见下）；会员端原有连错 5 次锁 30 分钟 |
| 错误泄露 | ⚠️→✅ 500 异常原文透传（含 PG 表名/约束名/SQL 片段）（本轮已修） |
| 默认密钥 | ⚠️→✅ JWT_SECRET 硬编码默认值（本轮已修）；PAY_ENC_KEY 默认值（告警+文档，见遗留） |
| 依赖 | ⚠️ 11 漏洞 → **9**（body-parser/qs 已 overrides 修复）；余项见「三、接受的风险」 |
| CORS | ⚠️ enableCors() 全开——评估为**可接受**（Bearer header 鉴权、无 Cookie，CSRF 无凭据可携带；同源端口/主机多变，收紧易破扫码场景） |

## 二、本轮加固（已落码并验证）

1. **登录/密保爆破防护**（新 `src/common/ratelimit.ts`，进程内存限流器）：
   - `POST /auth/login`：同工号连错 **5 次锁 15 分钟**（成功清零；工号不存在同样计数，兼防枚举）+ 同 IP **100 次/5 分钟**；
   - `POST /auth/forgot-password`：同工号密保答案连错 **5 次锁 30 分钟**；
   - `GET /auth/security-questions/:empNo`：同 IP 30 次/5 分钟（防工号/姓名批量枚举）；
   - `POST /auth/qr-login`：同 IP 30 次/5 分钟兜底（票据本身 128bit 随机无爆破面）。
   - 实测：连错 5 次后返回 `42901 密码连续错误已锁定，请 15 分钟后再试`；正确密码登录不受影响。
2. **JWT 密钥引导**（`src/common/auth.ts`）：未配置 env 时首启生成 48 字节随机密钥持久化 `backend/.runtime/jwt-secret`（0600），杜绝源码即密钥；换机迁移该文件或改配 env。**注意：本轮升级会使旧 token 全部失效一次（重新登录即可）**。
3. **500 错误信息不透传**（`src/common/http.ts`）：未知异常详情写 `logs/error.log`，客户端只收通用文案；DB 连接类异常返回友好提示（不含连接串/结构细节）。
4. **启动安全告警**：ADMIN 仍用默认密码 admin123 → 控制台 ⚠️；PAY_ENC_KEY 未配置 → 提示默认主密钥风险与加固路径。
5. **依赖加固**（package.json overrides）：body-parser ^1.20.8、qs ^6.16.0（传递依赖强制升级，express 4 兼容）。

## 三、接受的风险（本地单店部署口径，建议随里程碑跟进）

| # | 项 | 等级 | 说明与建议 |
|---|---|---|---|
| R1 | xlsx 0.18.5（高：原型污染/ReDoS） | 高·无官方修复 | 仅店内员工经 Excel 导入商品档案使用，文件来源可信；建议后续迁移 exceljs |
| R2 | multer ≤2.2.0（高） | 高·无暴露面 | 传递依赖，本系统上传全走 base64 JSON，未启用 multipart；随 @nestjs 升级自然解决 |
| R3 | @nestjs/core 10（中） | 中 | 修复需升 v11（破坏性），随框架升级里程碑处理 |
| R4 | PAY_ENC_KEY 默认主密钥 | 中低 | 已告警；换主密钥需重存各支付 secret（会有一次性运维动作），建议开业前决定 |
| R5 | signatures/uploads 静态无鉴权 | 低 | 签字图片文件名随机（时间戳+6 位随机）不可枚举；纯内网；如需严格可改带权限的图片端点 |
| R6 | CORS 全开 | 低 | 无 Cookie 凭据，攻击站点拿不到 Bearer token；保持现状 |
| R7 | 限流器重启清零 | 低 | 已知取舍（单实例内存态）；如需持久化可落 DB（member 表同款方案） |
| R8 | 会员 H5 密码策略 6 位起 | 低 | 员工端已有 4 档策略（V4.14.1）；会员端建议同口径跟进 |
