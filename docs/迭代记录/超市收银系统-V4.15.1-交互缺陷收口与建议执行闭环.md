# 超市收银系统 V4.15.1 — 交互缺陷收口与建议执行闭环

## 一、AI 训练台「屏幕渲染异常：pagerBar is not defined」
- 根因：V4.14.9 样本库改造用了 `pagerBar()/bindPager()` 但 ai.js 的 import 漏了这两个具名导出（ES Module 未导入标识符直接 ReferenceError，整屏渲染中断）。
- 修复：`import { openDetailModal, pagerBar, bindPager } from '../common-ui.js'`。

## 二、会员列表「下一页跳空白页」
- 根因：会员列表翻页按钮是**静态 HTML 且从未设 disabled**，`page++` 无上界——翻过界后拉到空页白屏，同时 `list()` 内部把 page 钳回 1，导致「上一页」判 `page>1` 为假也失效，只能查询强制刷新。
- 修复：`#mNext` 先按当前 total 算总页数、有下一页才翻；`list()` 增加防御——越界空页自动回退末页重拉。
- 通病排查：其余服务端翻页模块（营销触达/销售流水/设置留痕/供应商变更单）的下一页按钮均在渲染时按页码**动态置 disabled**，无此问题；本地分页（paginate/pagerBar）自带钳制，无此问题。本问题仅会员列表一处。

## 三、采购入库：表头复选框恒勾 + 每页 15 条
- 恒勾根因：全选态 `allChecked = rows.every(非未审核且非作废 || 已选)`——当列表**全部是不可勾选行**（如全部已审核）时 every 恒真，表头渲染 `checked`；且每次 onchange 触发 loadList 重渲染又算出 true，用户怎么点都弹回勾选。
- 修复：全选态只统计「可勾选行（未审核/已作废）」：`deligible.every(已选)`，无可勾行时不勾。
- 分页：列表改**每页 15 条**本地分页，接统一 pagerBar（右对齐+页码+手输跳页）。

## 四、弹窗双关闭按钮
- 根因：`openDetailModal` 的 h3 里自带一个 `cdm-close` ✕，而 app.js 的 MutationObserver 又对每个 `.modal-mask` 调 `decorateModal` 挂窗口按钮（— □ ✕）——同一弹窗右上角叠出两个关闭，内容里的那个被窗口按钮盖住（截图红框）。
- 修复：删除 openDetailModal 内的 cdm-close，只保留 decorateModal 的窗口 ✕（点遮罩关闭照旧）。全局生效。

## 五、库存总览「勾选生成订货单」改弹窗编辑式
- 原行为：勾选后一键按公式静默生成，用户无确认机会。
- 新行为：点「勾选生成订货单」弹**订货单编辑弹窗**（采购订单样式）：
  - 自动填充**建议数量**（= 下限×2 − 现有库存，可改）与**最近一批进价**（inventory.summary 新增 `last_cost` 子查询，可改）；
  - 每行复选框（表头全选）——不想订的行取消勾选；行小计与预估金额实时合计（无进价行不计）；
  - 确认后走原 `/purchase/orders`（source=库存缺货）按供应商自动拆单；进价随行传 `price` 落 PO。

## 六、智能决策中心 · 建议明细闭环
### 6.1 「动销周转打分」（选品）明细人话化
- 原先点开是裸 JSON。现渲染为可读表格：商品/类别/库存/近7天销量/周转天数/售价/打分/建议，列表简述同步人话化。
- **大模型选品推荐留待 AI 专项**（按用户指示）。
### 6.2 弹窗处置按钮
- 待处理建议的明细弹窗底部常驻 **「✔ 执行 / ✗ 否决」**；否决仍走样式化原因输入。已处理建议保持只读。
### 6.3 可编辑明细（定价 + 补货）
- 定价明细列：**进价｜原售价｜建议价｜实际价｜建议折扣｜实际折扣｜利润率**（+临期剩余天数/近7天销量；原因并入商品名下方）。
  - 实际价默认=建议价；改**实际价**→实际折扣自动算；改**实际折扣**→实际价自动算（双向联动）；
  - 利润率 =（实际价 − 进价）÷ 实际价，实时显示（无进价显示 —）；
  - 「折扣」已改名「建议折扣」（只读列）。
- 批量操作：首列复选框+表头全选；**批量改折扣**（输入 X 折应用到勾选行）；**移除所选行**（仅退出本次执行范围，不改建议原文，删后自动重编号）。
- 补货明细：勾选行可改订货数量、可移除行。
### 6.4 执行真生效 + 学习库（后端）
- `POST /brain/suggestions/:id/execute` 新增 body：`payload`（用户确认后的明细覆盖）与 `learning`（学习摘要）。
  - **定价域**：逐行按 `actualPrice` 真改 `products.sell_price`（≥原售价的行跳过并点名提示），执行后回 `note`「已按确认价更新 N 个商品售价」；
  - **补货域**：按 `actualQty` 生成采购单（原来固定取 suggestQty）；
  - 用户改动过的明细以 `payload.final` 回写建议留痕；
  - `learning.content` 写入知识库 `ai_kb_documents`（source_type=**执行学习**）+ 分块，累计店长定价/订货偏好，供后续建议收敛（前端每次执行自动生成「AI 建议 vs 最终定价」逐行摘要）。
