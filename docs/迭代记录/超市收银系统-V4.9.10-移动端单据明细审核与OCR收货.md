# 超市收银系统 V4.9.10 —— 移动端单据明细 / 审核 / OCR 收货落地

日期：2026-09-08　范围：员工移动端 PWA + 后端 OCR 权限口径　回归：19/19 通过

## 一、问题背景（用户原话锚点）

> 移动端中，管理员（有权限员工）看不到移动端中的表格明细（单据页中的单据明细），也无法通过手机审核/驳回单据等操作。移动收货中没有 OCR 扫码供应商送货单的入口，这个功能也是方案中有要求的，通过 OCR 扫码送货单进行收货入库。

排查结论：**三个问题全部是"后端已具备、移动端前端未接"**——

| 问题 | 根因 |
|---|---|
| ① 单据明细不可见 | `pwa/docs.js` 列表被 `employee_id === ME.staffId` 硬过滤（管理员没亲手建单就整页空白）；且列表行无 onclick，明细接口（`GET …/:id`）从未被调用 |
| ② 手机无法审核/驳回 | 后端 audit/reject 接口齐全（桌面 boss 端在用），PWA 零调用、零 UI |
| ③ 收货无 OCR 入口 | `work.js` 的 `openInvoiceModal`（票据 OCR）**只定义了从未被调用**；且接口权限卡 `ai.train.launch`，收货员会被 403 |

## 四、移动端使用说明

1. **单据**：底部「单据」→ 顶部类型筛选 + 全店/我的切换 → 点任意单据进明细 → 待审单据底部有「✖ 驳回」「✔ 通过」；按配置需签字时会弹手写签名板，签完自动继续审核。
2. **审核权限**：入库审核=入库审核权限点、退货=退货审核、盘点=盘点审核、报损=报损登记权限点；无权限者可见明细但按钮不出现（提示联系管理员）。ADMIN 或持 `*` 者全通过。
3. **OCR 收货**：工作台 → 移动收货 → 选供应商 → 「📄 扫送货单（OCR 收货）」→ 拍供应商送货单（或文本模式）→ 识别预览（商品匹配/低价保护）→ 生成入库草稿 → 单据页可明细核对并直接审核/驳回。

## 五、已知边界与后续建议

1. OCR 拍照识别依赖 `ocrImageToText`（本地 OCR），潦草手写送货单识别率有限，可切文本模式兜底；后续可切 Qwen2.5 VL 做票据版面理解提升识别率。
2. 单据列表一次拉全店数据（41 条量级无压力），单据量大后建议后端加分页。
3. `auth.sign_required_scenes` 含 recon（对账确认）——对账确认的移动端入口本期未做（boss 端已有），后续可按需补。
