## ① 后台首页天气 16.8~31.1℃ 与和风 19~24℃ 差距巨大 —— 已修复 ✅

**根因链**：
1. 你填的和风 API Host 是 `k85rk8g288.re.qweatherapi.com`——**没带 `https://` 前缀**；
2. 后端拼接请求 URL 变成 `k85rk8g288.re.qweatherapi.com/geo/v2/city/lookup`（非法 URL），请求直接抛错；
3. 天气服务**静默回落**到 Open-Meteo 免 Key 源（界面无任何提示），16.8~31.1℃ 就是 Open-Meteo 的数据——和你的和风 Key 无关，Key 本身完全有效（已直连验证：GeoAPI 正确返回岳池 101270802）。

**修复**：
- 后端对 Host **自动补 https:// 前缀**（你不用改任何配置）；
- 首页天气卡新增**数据源标签**（「· 和风」/「· OM源」），以后一眼就能发现回落；
- 清缓存重拉实测：**provider=qweather，岳池县 19~24℃ 阵雨**，与和风 App 完全一致。

## ② 供应商管理行高暴涨 + 无翻页组件 —— 已修复 ✅

- **行高根因**：上一期加的表格定高 CSS 里有一条 `.tbl-min > table { min-height:100% }`——Chrome 对表格设高度会把多余高度**按行均摊**，4 行数据每行被撑到 ~90px。已删除该条（容器定高保留，表格自然行高），**全站受影响的表格一并恢复正常**。
- **翻页根因**：翻页条在「只有一页」时被隐藏。已改为**常驻显示**：`‹ 上一页 · 第 1/1 页 · 共 4 条 · 下一页 ›`（单页时按钮置灰）。其他页用的公共分页条本就常驻，无此问题。

## ③ 决策自动化设置红框里的「鬼」—— 已修复 ✅

红框里是**裸 JSON 文本**（`"定价": "手动确认", "补货": …`）。根因：设置页控件渲染函数顶部有一条「json 类型 → 直接用 JSON 文本框」的**早退分支**，排在决策自动化的友好编辑器特判**之前**，导致上一期写好的分域下拉永远走不到（死代码）。

修复后：
- **决策自动化三档开关** → 补货 / 定价 / 备货 三个域各一个「手动确认/半自动/全自动」下拉；
- **决策自动化成熟度门槛** → 三个数字输入（采纳率≥N% · 连续达标N周 · 已决策样本≥N条），失焦即保存。
