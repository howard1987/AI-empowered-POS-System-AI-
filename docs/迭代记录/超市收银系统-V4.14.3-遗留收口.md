## 一、init-db 全量重放修复（V4.14.0 遗留#4，真因落定）

**两个叠加根因**：
1. **整文件单事务执行**：init-db.ts 用 `pool.query(整文件)` 发送，PG 规定 `ALTER TYPE ... ADD VALUE` 的新枚举值**禁止在同一事务内使用** → 全新库上 058（ADD VALUE '定时打折' 等随后即 INSERT）必报 `unsafe use of new value`；已有库因值早已存在而侥幸通过。
2. **roles 种子无幂等防线**：`roles` 表无 `(store_id, name)` 唯一约束、种子为裸 INSERT——半初始化库重放会插出重复角色，进而使「超级管理员=全部权限点」绑定子查询报 `more than one row`（即 V4.14.0 记录的「001 报错」真身）。

**修复（三层）**：
- `src/scripts/init-db.ts`：改为**语句级执行**（dollar-quote/引号/注释感知切分，每条独立隐式事务）；「already exists/duplicate key」逐条跳过并计数，其余错误带「第 N/M 条 + SQL 片段」报错。副作用：001 在已有库上不再整文件跳过，剩余幂等语句可逐条补齐。
- `db/001_init.sql`：roles 表定义加 `UNIQUE (store_id, name)`；roles 种子改 `INSERT...SELECT...WHERE NOT EXISTS`（**不依赖约束**，存量库 060 前也幂等）；stores 种子加 `ON CONFLICT (id) DO NOTHING`；绑定子查询限定 `store_id=1`。
- `db/060_v4143_roles_idempotent.sql`（新，幂等）：存量库 roles 去重（同店同名保留最小 id：先并权限点→迁员工绑定→删重复行）+ 补 `roles_store_name_uq` 唯一约束。主库已应用（无重复数据，约束已加）。

**验证**：空库 `pos_init_test` 首装 001~060 全过（106 表、roles=5、role_permissions=101、ADMIN=1）→ 同库二次重放全幂等 → 测试库已删除。
