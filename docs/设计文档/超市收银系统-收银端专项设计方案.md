## 1. 背景与现状

### 1.1 现状盘点（代码事实）

- 收银目前是 **PWA「作业」Tab 里的一个子视图**（`checkout.js` 856 行），入口层级深（开 PWA → 作业 → 收银），与入库/盘点混在同层，风格互相牵制；
- 已有能力：价目表 IndexedDB 离线缓存、扫码枪直扫/搜索联想、购物车、现金/扫码/余额三种支付、扫码通道真扣款（USERPAYING 轮询）、挂单/取单、扫码购核销、语音播报、电子秤读重（串口）、漏扫检测、应急收银、断网暂存补传、条码秤格式解析、即时秤贴；
- 设备连接入口在「我的-设备管理」（V4.15.3 收敛），但**无状态感知、连接不持久、失败静默降级**；
- 支付只有三选一，**无找零界面、无组合支付**；退货要去作业页跨页面；无交接班界面。

### 1.2 问题定性

收银是全店**最高频、设备最密集、资金风险最集中**的操作。本次专项按「一单的完整生命周期 + 人钱物流动」全面梳理，补齐功能、异常路径与设备底座三块。

## 3. 载体与范围：A + C 双端

### 3.1 A 端 · PWA 独立收银台（先做）

- PWA 内新开**一级「收银」入口，登录后直落全屏收银台**，无底部 Tab 干扰；
- 手机/平板/收银机浏览器通用；收银机 PC 开浏览器全屏也可用；
- 复用现有底座：离线价目表、支付通道、设备连接、小票/钱箱钩子——改动集中在信息架构与布局层。

### 3.2 C 端 · PC 收银机专属端（基于已实施 Electron 端演进）

> **修正（2026-09-11 补确认）**：初始版已实施 Electron 收银端 `frontend-desktop`（V4.8.x，Win7/Win11 安装包齐备），P16 **不新建**，在其基础上按新设计补功能。

- 保留已验证底座：**双屏输出（主屏 kiosk 全屏 + 副屏顾客信任屏）**、外设适配器（serialport 直驱）、小票模版、安装包链路；
- **副屏已实施元素全保留**：明细逐行滚动、应收金额大字、「会员已帮您节省 ¥X」、会员卡（脱敏手机、储值/可用分红/积分、等级系数、终身累计与**失效分红透明展示**）、支付成功页（欢迎再次光临）；
- **副屏增强（P16）**：① 支付过程引导——扫码时「请出示付款码」大字→出码引导，现金时显示应收/实收/找零大字；② 店招+欢迎语常驻顶栏；③ 空闲轮播内容后台可配（活动图文/分红池公示/会员招募文案存 system_settings）；
- 设备通道：以 **Electron 原生适配器为主**（serialport 直驱，无浏览器手势限制），网口设备走后端转发——替代此前「纯浏览器通道」预设；
- **F1~F12 键盘流**（快捷键体系见 §12.1）；
- 复用 A 端全部后端接口与数据层。

## 4. 布局与视觉

### 4.1 A 端响应式双布局

| 设备 | 布局 |
|---|---|
| 手机竖屏 | 单栏上下流：顶部设备灯+搜索/扫码 → 快捷格 → 购物车 → 底部深色合计/支付条（拇指热区） |
| 平板横屏 / C 端 | 双栏（**左商品右购物车**，与已实施 C 端同向）：左扫码/搜索+分类+快捷格+功能格，右购物车+合计/支付条 |

### 4.2 视觉规范

- **基调**：延续全店浅色 + 品牌绿；合计/找零/支付区用**深色高对比条**突出金额（≥28px 加粗）；
- **密度**：大按钮低密度，触控目标 ≥48px——收银是操作不是浏览；
- **设备状态灯**：顶部常驻四盏（扫码枪/电子秤/小票机/钱箱），绿=在线、红=掉线可点重连、黄=降级通道。

## 6. 设备连接方案（八项）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 状态感知 | 收银台顶部常驻四盏设备灯，进收银台自动检测一轮，掉线可点重连；班前「一键连齐全套」 |
| 2 | 连接持久化 | 指纹记忆（端口标识/网口 IP/蓝牙名）+一键重连；WebSerial 仍需一次手势（浏览器硬限制），网口设备走后端免手势直连 |
| 3 | 扫码枪 | 收银台运行期**全局键盘监听**（HID 枪特征节奏收码，不依赖焦点，弹窗/结算页都能收）；手机配隐藏输入框防软键盘；不换枪 |
| 4 | C 端通道 | 基于**已实施 Electron 端演进**：设备通道以 Electron 原生适配器为主（serialport 直驱，无手势限制），网口走后端转发；不做浏览器本地打印代理 |
| 5 | 绑定粒度 | C 端设备绑**台位**（存台位档案，换人接岗不重连）；A 端手机设备绑**登录人** |
| 6 | 打印降级 | 网口失败→自动试串口→再试系统打印，**每级明示实际通道**；全失败才报错给重试；状态灯同步变黄 |
| 7 | 手机连秤 | 维持手输重量（放开安卓串口秤被否，规避 OTG 线材支持问题） |
| 8 | 语音播报 | 默认本机喇叭，蓝牙音箱可选自动切换 |

**现状病灶对照**：设备无状态感知（用到才报错）→ 状态灯+自检；连接不持久（刷新即忘）→ 指纹+一键重连；打印静默降级 → 明示通道。

## 8. 设置与权限

- 设置项**内嵌收银台**：店长权限的「⚙ 收银设置」面板就地改（快捷格数量、抹零方式、退货限额、交接班容差、锁屏超时、积分比例、语音开关、客显文案等）；
- 底层仍存 `system_settings` 同一套键，日后迁系统设置页只需换入口；
- 权限主线：抹零/赠品/开放键可选权限、整单自定义折扣、最低售价放行、退货超限、无交易开钱箱、挂账超限——全部留痕进操作记录。

### 13.10 负库存售卖与账实容错（2026-09-11 用户追问补充）

**背景**：账实不符是超市常态——货先到未入库、退货未及时清点回库、盘损未调账。若收银端按库存硬拦，顾客会因后台账务滞后买不到货，收银丢单损失远大于账面负库存。

| 决策点 | 结论 |
|---|---|
| 默认策略 | 收银端库存**只提示不硬拦**：超库存 / 零库存售卖给红色警示 + 确认弹窗，确认后按**负库存**成交并留痕（品名/账面库存/车上数量/实卖数量/操作人/时间） |
| 可配置 | 收银设置加「库存硬拦」开关（**默认关**）；开启后超库存一律拒绝（谨慎型门店可选） |
| 留痕闭环 | 本班负库存单自动进「负库存清单」（店长面板可查），交接班 / 日结提示本班负库存 N 笔——差异要暴露，驱动及时入库 / 盘盈调整，而不是靠拦截掩盖 |
| 沽清语义调整 | 沽清（库存 0）从"禁售"调整为"警示 + 可确认售卖"（账面 0 不代表货架没有）；置灰样式保留防误触 |
| 开发注意 | ① 后端 FIFO 批次扣减需支持负批次挂起（不按 0 成本静默吞掉，待盘点调整回填成本）；② 防超卖 CAS 仅在硬拦开启时强制，默认模式改为"逐笔负库存留痕"；③ 前端拦截只是体验层，一切以服务端落账为准 |
