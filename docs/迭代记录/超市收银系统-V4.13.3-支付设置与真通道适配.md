# 超市收银系统 V4.13.3 — 支付设置（密钥加密）+ 微信/支付宝真适配器

> 日期：2026-09-09 · 设计方案 14.22 节 · 回归 17/17 + V4.13.2 25/25 + V4.13.1 12/12 + Web 后台实机抽查 3/3

## 一、结论：模拟通道填了 API 能正式启用吗？

**V4.13.2 时不能**——MockPayAdapter 写死「即时成功」，不读取任何配置。本期改造后：**后台填齐 API 配置 → 启用对应渠道 → 通道模式切 `real`，即正式启用真通道收款**（微信 V3 付款码支付 / 支付宝当面付），收银台流程不变：扫顾客付款码 → 真通道扣款 → 成功信号自动落单。

## 二、落地内容

### 2.1 支付设置组（050 迁移，「支付」分组 13 项）
- 通道模式 `pay.gateway.mode`：off（记账式+二次确认）/ mock（模拟）/ **real（真实通道）**
- 微信：enabled / mchid / appid / cert_serial / gateway + **secret：apiv3_key、private_key**
- 支付宝：enabled / app_id / gateway + **secret：private_key、public_key**

### 2.2 密钥加密三原则（`common/secret.ts`）
1. **落库即密文**：AES-256-GCM（`enc:v1:iv:tag:ct`），主密钥 env `PAY_ENC_KEY`（缺省本地派生，换机需同 key）
2. **接口只出脱敏**：GET 返回「未配置 / ••••尾号」，明文密文不出服务端
3. **留痕/审计只记脱敏值**：setting_change_logs、audit_logs 无明文
- 编辑约定：留空=不修改、传回掩码=不修改、新值=覆盖重加密

### 2.3 真适配器（`pay.adapters.ts`，零 SDK 纯 Node crypto）
| | 微信 V3 | 支付宝当面付 |
|---|---|---|
| 扣款 | POST /v3/pay/transactions/codepay | alipay.trade.pay（scene=bar_code） |
| 退款 | /v3/refund/domestic/refunds | alipay.trade.refund |
| 签名 | SHA256withRSA（WECHATPAY2-SHA256-RSA2048 头） | RSA2（参数 ASCII 升序） |
| 验签 | ⏸ 一期直连 HTTPS 不验平台证书（上线前补） | ✅ 应答 RSA2 验签，失败拒绝结果 |

- 配置缺失 → **40904**（提示缺哪些字段，不发请求）；渠道未启用（收款）→ **40905**；通道失败 → FAIL 流水 + failMsg 透出（不抛 500）
- 退款：real+渠道启用 → 真通道原路退；未启用 → 回落 mock 兜底（不阻断内部退款）
- **实测坑**：catch 必须重抛 BizException，否则配置缺失 40904 被吞成「网络异常」

### 2.4 UI
- **Web 后台 · 系统设置**：支付分组——secret 密码框（「输入新密钥覆盖」+「已加密配置 ••••尾号」），mode 三态下拉，行内保存
- **Boss 端 · 设置**：新增「💳 支付通道设置」专页——模式切换 + 微信/支付宝配置卡（分组保存、开关即点即存）

## 四、使用指引（资质办好后三步启用）
1. 后台 → 支付通道设置 → 模式切 **real**
2. 填齐对应渠道配置并启用（微信：商户号/APPID/证书序列号/APIv3 密钥/商户私钥；支付宝：APPID/应用私钥/支付宝公钥）——密钥保存后只显尾号
3. 收银台照常扫顾客付款码：真通道扣款 → 成功自动落单（mode=off 随时可回退记账式）

**遗留**：微信平台证书验签、USERPAYING 查单轮询、开钱箱+小票打印钩子、扣款前取服务端预计价、网关流水接入对账。
