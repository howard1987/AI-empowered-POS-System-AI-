## 一、电子签名管理（4 项）

### 1. 新增/补签自动识别姓名 + 关联供应商采集样本（签字1）
- **AI 识名**：新端点 `POST /ai/signature/read`（ai.ocr.ts 新增 `AiSignatureController`）——本地 VL 模型
  （`ai.ocr.vl_model`，Ollama /api/generate）读手写签名输出 2~4 字姓名；未启用/不可达返回空名+提示，前端回退手填。
- **供应商自动关联**：识别姓名与 `suppliers.contact_person` 归一化一致 → 采集弹窗自动选中该供应商并填身份=业务员；
  非供应商侧（报损/盘点等）不关联供应商。
- **样本库不缺人**：现场补签（`POST /purchase/signatures/attach`）保存调用记录后**自动采集进样本库**——
  供应商侧按 `supplier_id+姓名` 幂等建档（role=业务员），无则建、有则追加画像；非供应商侧按 `ref_employee_id`
  采集店员样本（不绑供应商）。助手 `collectIntoTemplates`（sign.ts）。

### 2. 签字完整性甄别（签字2，防假签/乱签/冒签）
- 后端 `nameMatches`/`normalizeName`（sign.ts）：归一化去空白/间隔点/分隔符后，**所签姓名必须完整包含单据署名**。
  期望姓名：入库/退货=供应商 `contact_person`；其余=操作店员本人。不符 → `50071` 拒绝并提示。
  - 例：署名张三 → 「张三」「张 / 三」「张三丰（含张三）」过；「张五」「刘三」「张」拒。
- 前端采集板乱签初筛：单遍笔画 <2 或墨迹 <0.1% 面积 → toast 拒绝记录。
- 单测：9/9 用例通过；e2e 实测张五/张被拒（50071）、张 / 三通过。

### 3. 至少 3 次采集形成签字画像（签字3）
- 预采集弹窗改**连签 3 遍**（`MIN_SAMPLES=3`）：每遍「保存」记录一块板面并清板继续，缩略图进度 n/3；
  提交 `images[]`（至少 3 张）。后端 createSignature 校验 images≥3（单张旧调用兼容）。
- `signature_templates` 新列（062）：`profile jsonb`（{images:[…], strokes, updated_at}）、`sample_count smallint`。
  现场补签自动采集同样累加画像（sample_count+1、profile.images 追加，上限 9 张）。
- 模板自动关联（autoAttachSignature）优先取 `sample_count>=3` 的满画像样本（ORDER BY CASE）。

### 4. 样本表操作增强（签字4）
- 每行「操作」列：保留 停用/启用，新增 **删除**（红色确认弹窗）。
- ID 列前新增**复选框列**（表头全选）+ 批量操作条：**启用 / 停用 / 🗑删除**（删除需确认）。
- 新端点：`DELETE /purchase/signatures/:id`、`POST /purchase/signatures/batch {ids, action: delete|disable|enable}`。
- 表格新增「画像」列（n 遍，≥3 绿色 / <3 黄色）。

1. **菜单顺序**：「电子签名管理」移到「系统设置」上方（app.js MODULES）。

## 四、AI 主模型不持久化修复（真因）

- 真因：`ai.models.ts` 的 `setSetting` 是 **UPDATE-only**——`system_settings.setting_key` 无该行时
  （如 `ai.llm.model` 从未被种子写入），UPDATE 影响 0 行被静默吞掉 → 界面上「候选→主模型」，
  重启后回读默认又变回「候选」。
- 修复：改 **UPSERT**（INSERT … ON CONFLICT (setting_key) DO UPDATE，组=AI赋能）。
- 实测：select 写入后库内 `ai.llm.model = "qwen2.5vl:3b"` 落行成功。
