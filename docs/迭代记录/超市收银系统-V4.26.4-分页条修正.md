# V4.26.4 · 分页条（上下页模块）修正

> 起因：老板报「供应商变更记录」页上下页模块未固定 —— 截图里分页条浮在表头之上，位置飘忽。
> 结论：**不是这一页的问题，是全局分页组件的缺陷**，40+ 处调用点一起受益。

---

## 一、现象（已无头复现）

`frontend-web/screens/suppliers.js` 的「🔁 供应商变更记录」卡片，页面滚到中间态时：

- 分页条 `‹ 上一页 / 第 N 页 / 下一页 ›` 脱离它所属的表格，**吸附到屏幕底边**，
  浮在表格行之上，把数据行盖住；
- 表格只有 1 条时更明显 —— 分页条直接压在表头和数据行之间，看着像"没归属"。

用 headless Edge 复刻同结构 DOM + 同 CSS（`#app` flex → `#view{overflow:auto}` → `.card` → `#chgList` → `table` + `.pg-bar`），
窗口 1280×420、`#view.scrollTop=380`，**稳定复现**：分页条压在第二行数据上。

---

## 二、根因

`common-ui.js` 的 `pagerBar()` 给分页条写死了 `position:sticky; bottom:0`
（V4.14.1 引入，本意是"长表格翻页不用滚到底"）。

但 `position:sticky` 的吸附参照是**最近的滚动容器**。后台的滚动容器是整页的 `#view`，
不是分页条所属的表格区域。于是：

- 分页条自然位置在表格下方，一旦滚出视口下沿，就被吸附到 `#view` 的**屏幕底边**；
- 它不再属于表格，视觉上就是"飘到别的行上面"；
- 表格越短（比如只有 1 条记录）越难看。

---

## 三、修法

### 1. `pagerBar()` 的 `sticky` 默认值 `true → false`

分页条默认**随表格流走**，待在表格正下方，不再吸底、不会浮出表格。
`sticky: true` 参数保留，向后兼容（`signatures.js` 早有显式 `sticky:false`，说明坑之前被人踩过）。

### 2. 新增宿主容器类 `.pg-host`（需要"固定底部分页"的表格用）

```css
.pg-host { max-height: var(--pg-max, 48vh); overflow: auto; overscroll-behavior: contain; }
.pg-host > .pg-bar, .pg-bar-sticky { position: sticky; bottom: 0; }
```

给承载表格的容器加 `.pg-host` 后：

| 场景 | 表现 |
|---|---|
| 内容不溢出（记录少） | 容器高度自适应，分页条自然跟在表格后面 —— **位置稳定，不浮动** |
| 内容溢出（记录多） | 容器限高内部滚动，分页条**固定在容器底部** —— 翻页不用滚到底 |

两种场景都对，所以这页（供应商变更记录）已按此改造。

### 3. `bindPager()` 加固

原实现 `root.querySelector('.pg-bar') ? root : null`：当 `root` 本身就是分页条时静默失效。
改为 `root.classList.contains('pg-bar') ? root : root.querySelector('.pg-bar')`。

### 4. `paginate()` 透传 `sticky`

`paginate(rows, page, size = 10, sticky = false)`。第 4 个形参原为没人用的 `onChange`（死代码），已清理。

## 四、改动文件

| 文件 | 改动 |
|---|---|
| `frontend-web/common-ui.js` | `pagerBar` 默认不吸底 + 注释说明坑因；`bindPager` 加固；`paginate` 透传 sticky、清理死代码 |
| `frontend-web/styles.css` | 新增 `.pg-host` / `.pg-bar-sticky` 规则 |
| `frontend-web/screens/suppliers.js` | `#chgList` 挂 `.pg-host`；卡片补 `padding-bottom:14px`；容器去掉 `padding-bottom`（避免分页条压住内边距） |

**没碰后端、没动数据结构、无需迁移。**

## 五、验证

- headless Edge 复刻同结构页面，修复前后对照：
  - 修复前 `scrollTop=380` → 分页条压在数据行上（问题复现）
  - 修复后同位置 → 分页条稳稳跟在表格下方
  - 12 行数据 + 容器内滚 150px → 分页条固定在容器底部
- `common-ui.js`、`screens/suppliers.js` `node --check` 通过
- `styles.css` 括号平衡 0 越界（顺带加了"③-3 注释独立成行"的回归检查项）
- 全库扫描：`paginate(...)` 零处显式吸底调用，40+ 处调用点行为一致收口

---

## 六、可选后续

以下页面是"长表格堆叠"，可按需给表格容器加 `.pg-host` 换取"固定底部分页"
（**非必须**，不加也能正常工作）：`recon.js`（往来账 / 结算单）、`bigcustomer.js`（弹窗内 3 张表）、`ops.js`。
新增约定：以后凡是给"表格容器"加 `.pg-host`，容器自身不要再写 `padding-bottom`（分页条会压住它），
底部留白交给外层卡片。
